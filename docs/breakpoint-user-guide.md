# 断点使用说明

适用于带“断点规则”和“待处理”入口的 macOS 桌面预览版。旧 GitHub 包不一定包含此功能，以实际界面为准。安装包内本说明名为 `BREAKPOINTS.md`。

断点用于在请求发出前，或响应返回应用前，暂停并修改本次内容。它默认关闭；不开启时继续普通抓包。只用于你有权测试的应用与接口。

## 前置条件

- 先按安装说明完成设备接入，开始一次抓包，并确认普通 Request / Response 能显示。
- HTTPS 必须已能解密。断点不能解决证书绑定、应用层加密、业务签名或不经过代理的流量。
- 不需要为断点另装证书、修改 VPN 或逐个添加手机域名。手机沿用已有抓包通道；若通道本身没接通，请先排查连接。
- 规则只绑定当前正在录制的抓包。历史记录、其他设备和已结束任务不能编辑发送；换任务或重启后需主动复用规则并启用。
- 优先选只读查询，不用支付、删除、账号权限等请求试验。暂停可能触发应用超时和自动重试。

## 第一次修改请求

1. 在“接口”页选择目标记录，点击“设置断点”；也可打开“断点规则”后点击“新建规则”。
2. 核对完整地址、方法和路径匹配。默认用“精确路径”和“仅下一次”，暂停阶段选择“发送请求前”，等待时限可选 15、30、60 秒。
3. 点击“保存并启用断点”。如果只点“保存规则”，还需要点击“启用断点”。
4. 回到设备重新触发该接口。旧记录不会自动重放。桌面“待处理”出现数量后打开并选择暂停项。
5. 在 URL 中修改同站点的路径或 Query；也可修改方法、可编辑的头和正文。点击“对照修改”核对原值与草稿，再点“应用修改并继续”。
6. 查看最终接口结果，确认服务器是否接受了修改。操作已受理或被代理采用，不代表服务器已执行成功。

规则按协议、域名、端口、方法和路径匹配，**不按 Query 参数匹配**；从 URL 建规则时不会保存 Query。精确路径 `/items` 不匹配其他路径；“路径前缀”会扩大范围，测试前需核对。多个重试请求可能竞争“仅下一次”，命中后规则显示“已命中一次”，下次需主动重新启用。需要连续调试时才选择“持续拦截”。

## 修改响应

1. 新建或编辑规则，将暂停阶段设为“返回响应前”或“请求和响应”。
2. 触发请求，等待响应暂停。双阶段规则会先暂停请求，请求继续后再暂停响应。
3. 修改响应状态码、可编辑的头或 JSON/文本正文，核对后点击“应用修改并继续”。
4. 在设备上检查实际展示，并在接口详情展开“断点修改记录”，对照“原始内容”和“生效内容”。

**响应暂停时，服务器已经处理了请求。** 修改返回内容不会修改服务器数据库；终止响应也不会撤销已执行的操作。对于 HEAD、204、304 等无正文语义，不能附带正文；编辑成无正文状态时先清空正文。

## 放行、终止与停止

| 操作 | 实际效果 |
| --- | --- |
| 保留原始内容并继续 | 放弃当前阶段草稿，按该阶段原始内容转发；双阶段规则可能继续暂停响应 |
| 应用修改并继续 | 校验通过后采用草稿并转发；不自动重试，不保证对端成功收到 |
| 终止本次请求 | 确认后结束本次连接；请求阶段尚未发给源站，响应阶段源站已执行，无法撤销 |
| 全部保留原始内容并继续 | 丢弃未应用草稿、释放暂停项并关闭断点，普通抓包继续 |
| 关闭断点 | 停止新拦截，未处理阶段按原始内容放行；已经采用的请求修改不会被撤销 |
| 停止抓包 | 结束本次录制与断点控制，保留结果；iPhone 的连接保留与网络恢复仍遵循原有流程 |

倒计时结束后会放弃当前阶段未应用草稿，按原始内容继续。桌面控制失联也有自动释放机制，但应用自身可能更早超时。正文未收集完就超时、客户端断开或代理崩溃时，连接可能失败，而非一定成功放行。过期草稿不能再次应用，需重新触发请求。

“清空列表”、关键词搜索、“仅看接口”、切换历史记录只影响接口显示，不会取消暂停；可从工具栏“待处理”入口继续处理。仅关闭断点面板不会关闭断点。

## 编辑与数据边界

- 支持 HTTP/1.1、HTTP/2 的普通请求和最终响应；不支持 WebSocket 消息、HTTP/3、gRPC/Protobuf 二进制正文或原始 TCP 编辑。
- URL 只能修改同源路径与参数，不能更换协议、域名或端口；不允许携带用户信息或片段。
- 正文编辑上限为 256 KiB，限可完整读取的 JSON、UTF-8 文本或 URL-encoded 表单。流式、二进制、大包和过度压缩正文不会以截断内容替换；不满足安全编辑条件时跳过断点或限制编辑。
- 头字段最多 200 行、合计 64 KiB；重复头按行保留。Host、Content-Length、编码与连接相关头、代理认证头由组件管理，不要手动修改。正文长度由工具重新计算。
- JSON 格式化需主动点击“格式化 JSON”，不会在打开时自动改写。非法 JSON 或不支持的字段会拒绝应用，草稿保留；也可直接选择原样继续。
- Authorization、Cookie 等敏感头默认遮盖，主动显示后才能编辑；占位文字不会当作真实值发送。真实头、URL 参数、正文及 cURL 仍可能含凭据，复制分享前自行脱敏。
- 归档保留原始和生效版本。断点详情正文预览限前 32 KiB；完整已归档内容仍在本机结果中。代理采用的版本不等于客户端实际收到，需结合设备和连接结果判断。

## 常见问题

**规则启用了却没有暂停？** 确认当前任务正在录制、断点总开关和规则都已启用，方法及协议/域名/端口/路径完全匹配，“仅下一次”尚未消耗。重新触发接口，不要只刷新桌面列表。大包或不支持的协议可能被安全跳过。

**提示当前抓包不支持断点？** 可能正在连接旧版后端或旧任务。先按正常流程停止任务，退出旧工具，再启动新版并新建抓包；不要在正在使用的任务上强制替换服务。

**修改后应用报错或显示没有变化？** 查看 Request / Response 和断点归档。应用可能校验签名、缓存结果或已超时；工具不会重算业务签名。先关闭断点确认普通抓包正常，再缩小修改范围。

**应用一直等待？** 打开“待处理”，选择原样继续；不再调试时使用“全部保留原始内容并继续”。不要反复提交相同业务操作。连接中断时查看“运行检查”，不要为断点更改原 VPN、节点或证书。

## 当前验证范围

BP-4 已验证包内三种代理适配的 HTTP/1.1/2 转发，以及 iPhone14_Test 的真实请求参数与响应改写，手机确认显示修改后的内容；PokeHub 普通业务抓包未修改。Android 真机本轮无设备，尚未完成现场断点验收，不能据此承诺所有真机或所有应用兼容。当前包仍为内部开发签名预览版，未完成 Apple 公证。
