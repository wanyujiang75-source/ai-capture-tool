# 抓包工具桌面端使用指南

本文面向在自己 Mac 上使用 `抓包工具.app` 的测试、产品和开发人员。桌面端运行于 macOS，
提供 Android 模拟器抓包及 iPhone HTTP(S) 代理抓包。新版预发布包包含“iPhone”入口，
已有 PokeHub、MelodyCraft、Wishly、StickerHub 业务实测；手机端仍需手动确认和切换，不能代表全部设备或应用兼容。
Windows、Linux 和服务器多人共享不在范围内。

使用 Android 手机请直接查看 [Android 真机操作流程](#android-physical)，不要按模拟器步骤安装系统镜像。只有带“真机（实验）”入口且包含连接助手的构建支持该流程；下载时核对 Release 说明是否包含该功能，旧版安装包不包含此入口。

## 1. 使用前准备

### 1.1 Mac 要求

- macOS 14 或更高版本。
- Apple Silicon（M1/M2/M3/M4）。当前内嵌运行时不支持 Intel Mac。
- 建议至少 16 GB 内存、25 GB 可用磁盘空间。Android SDK、Google Play 系统镜像和
  模拟器数据占用主要磁盘空间，抓包工具自身约 256 MB。
- 能访问 Google Android 仓库；安装 Jenkins 测试包时还需连接公司内网或 VPN。

上述内存、磁盘和 Android 仓库要求主要针对模拟器。仅使用 iPhone 时不需要 Android SDK
或 Android 系统镜像，但需要手机与 Mac 在同一可互通的网络中。iPhone 流程见第 13 节。

### 1.2 Android 模拟器要求

桌面 App 已包含抓包后端、mitmproxy 和 Frida 客户端，但不把 Android SDK 和系统镜像打进
安装包。新 Mac 需要先安装 Android Studio，或至少安装 Android command-line tools，并确保
以下命令可用：

```bash
adb version
emulator -version
sdkmanager --version
avdmanager list avd
```

Android SDK 默认从 `$ANDROID_SDK_ROOT` 或 `~/Library/Android/sdk` 查找。建议先打开一次
Android Studio，完成 SDK License 接受和基础组件下载。

## 2. 安装桌面 App

完整安装路径见 [安装指南](../INSTALL.md)，其中包括 Codex 辅助安装、手动下载、源码构建、升级和新主机配置。下面是手动安装的最短流程：

1. 下载 `AI-Capture-Desktop-*-arm64.zip`。
2. 校验下载页面提供的 `.sha256`（可选但推荐）：

   ```bash
   shasum -a 256 -c AI-Capture-Desktop-*.zip.sha256
   ```

3. 解压 ZIP，把 `抓包工具.app` 移入 `/Applications`。
4. 双击打开。正式公证包应直接通过 Gatekeeper。
5. 内部预览包如果显示“Apple 无法验证‘抓包工具’”，点击“完成”，不要点击“移到废纸篓”。打开
   “系统设置 -> 隐私与安全性”，向下找到该 App 的拦截提示，点击“仍要打开”，完成 Mac 登录验证后再确认“打开”。

“仍要打开”通常只在尝试启动 App 后约一小时内显示。参考 [Apple 官方操作说明](https://support.apple.com/zh-cn/guide/mac-help/-mh40616/mac)。

不要直接在 ZIP 预览窗口内运行 App，也不要移动或删除 App 内的 `Contents/Resources`。

## 3. 第一次准备 Android 环境

打开 App 后默认进入“抓包”。本机服务由桌面 App 自动托管，无需运行 `start.sh`，也无需打开
`127.0.0.1:7001`。主导航只有“抓包、安装应用、接口、日志”四项。

首次使用按以下顺序操作：

1. 点击“开始抓包”。工具会自动检查 Android SDK，并准备一台符合条件的 Google Play 模拟器。
2. 首次下载 Android 镜像可能需要数分钟。页面会依次显示“正在启动模拟器…”和“正在启动 Android…”，请保持窗口打开。
3. 页面显示“等待解锁”时，在模拟器中手动解锁；解锁后流程会自动继续。
4. 页面显示“等待应用”时，在模拟器中打开需要分析的应用。工具识别前台应用后，会自动检查网络和抓包组件并开始记录接口。
5. 如果应用依赖 Google 登录，在模拟器中打开 Play Store 并手动登录。公司内部模式默认不强制
   Google 登录；启动 App 前设置 `REQUIRE_GOOGLE_LOGIN=1` 可启用严格准入。

不需要依次点击“发现设备、准备组件、启动测试”等按钮。普通流程只需一次“开始抓包”；需要排错时，再点击工具栏中的“运行检查”。

自动准备只操作本项目设备、端口和进程。发现端口被其他程序占用时只会报错，不会终止其他项目。

模拟器性能按宿主机自动选择：16 GB 及以上内存且至少 8 个逻辑核心时使用
`4 核 / 4096 MB / GPU host / 8 GB 数据分区`，资源较低时使用 `2 核 / 2048 MB` 均衡档。
如果同名 AVD 已存在但不是 Google Play 原生架构镜像，桌面端会保留原 AVD，自动创建或复用
带 `_GooglePlay` 后缀的合规替代设备并切换抓包设备绑定。它不会覆盖、wipe、删除原 AVD，也不会
随机调用用户的其他模拟器。

## 4. 安装应用

安装来源与抓包目标相互独立。Jenkins、本地 APK、Android Studio、ADB 或其他工具都只负责把 App
安装到设备；抓包目标始终由模拟器当前前台 App 决定。

### 4.1 本地 APK

在“安装应用”页点击“选择 APK”。桌面端会把 `.apk` 安装到
当前设备并登记为生产包。安装完成后，在模拟器中手动打开该 App；不需要再到应用库选择一次。

如果模拟器未启动、Android 仍在启动或屏幕尚未解锁，页面会直接说明当前问题和下一步操作，不会显示后端原始错误。

### 4.2 Jenkins 测试包

“安装应用”页会读取 Jenkins 企业构建任务的最新 APK：

1. 先选择已启动、已解锁的安装设备。
2. 找到目标构建，点击“安装”。
3. 页面显示“正在下载并安装‘任务名’#构建号…”时保持模拟器在线。
4. 安装完成后，包名、Activity 和版本信息会同步到本机应用库。
5. 在模拟器中打开刚安装的 App，抓包页会自动识别它。

Jenkins 只是测试包来源，不会自动成为当前抓包目标，也不会覆盖正在分析的 App。

当前本地入口支持单个 `.apk`。复杂 split APK、`.apks` 或 `.zip` 仍属于高级接口能力。

### 4.3 其他安装方式

通过 Android Studio、ADB 或其他安装工具预先安装的 App 无需导入应用库。只要包已安装且能在设备
前台打开，桌面端会自动读取包名、Activity 和版本；未登记的 App 会以 `production + auto` 幂等登记。

Launcher、System UI 和锁屏不会被误登记为业务 App。

### 4.4 Jenkins 无法加载

先确认 Mac 已连接公司内网或 VPN，并可访问页面显示的 Jenkins 地址。默认配置允许匿名读取；
需要账号时由管理员通过运行环境提供：

```bash
export JENKINS_BASE_URL="http://jenkins.example.internal:8080"
export JENKINS_USERNAME="jenkins-user"
export JENKINS_PASSWORD="<从安全存储读取>"
open -na "/Applications/抓包工具.app"
```

不要把真实密码写入仓库、截图、抓包说明或共享脚本。

## 5. 启动抓包

推荐顺序：

1. 在“抓包”页点击“开始抓包”。单设备时不会显示设备选择器；只有检测到多台设备时才显示“使用设备”。
2. 工具会自动启动模拟器并等待 Android 完成启动。屏幕锁定时会显示“等待解锁”。
3. 在模拟器中打开目标应用；工具自动识别前台应用并准备网络和抓包组件。
4. 状态显示“正在抓取‘应用名’”后，在模拟器中操作需要分析的功能。
5. 捕获接口后页面显示“已捕获 N 个接口”；进入“接口”查看实时请求。
6. 完成后点击“停止抓包”。停止会保留本次结果，同一前台应用可立即开始下一次抓包。

如果抓包运行期间切换到另一个应用，桌面端不会直接覆盖当前任务，而是显示“其他应用正在抓包”，
并提供“停止并切换”和“继续当前任务”。

不要同时在同一设备启动第二个抓包任务。桌面端检测到同一应用已有抓包时会自动恢复；需要重新开始时先点击“停止抓包”。

## 6. 查看接口

“接口”页会实时同步当前抓包，最新接口显示在列表顶部。点击一条记录后可切换：

- `Request`：查询参数、请求 Headers 和 Body；GET 请求可能没有 Body，参数仍会在查询参数区域显示。
- `Response`：响应状态、Headers 和 Body。请求体为空但响应存在时，页面优先打开 Response。
- `cURL`：用于复现请求的命令，可能包含本机测试账号的 header 或 token，分享前必须脱敏。

JSON 正文会按层级缩进，每个键值对独立换行；URL 查询参数、表单和 Headers 按字段分行，重复字段不会合并。
点击详情文本后可以拖选多行，或按 `Cmd+A`、`Cmd+C` 复制整个详情（包括参数、Headers 和正文）；只需要正文时选中对应区域即可。复制或分享前请检查并脱敏 Authorization、Cookie 等敏感字段。

显示只使用实际已保存的数据。旧记录缺少 Headers 会明确提示；二进制正文不转成乱码，已有正文文件时提供 Finder 入口。
正文仍采用最多 256 KiB 的输入预览；格式化另有输出、行数和层级限制，超限或非法 JSON 保留原始预览。
“正文预览不完整”表示内容被截断、未完整捕获或未完整解码，不代表没有响应，也不保证归档文件完整。

页面默认显示正在进行的抓包；没有运行任务时显示“尚未开始抓包”，不会自动加载上次结果。
同时有多个抓包任务时才显示“切换抓包”。Android/iPhone 合计仅保留最近 7 次已结束或中断的抓包，按记录编号从新到旧排列；正在启动、运行或停止的抓包不计入这 7 次。服务启动、抓包结束时自动删除更早的记录及其抓包文件，删除后无法在工具中恢复；需要长期保存的数据请提前另存。
“历史记录”可按应用、平台、日期或记录编号搜索；每条记录显示开始时间和“已结束 / 已中断”等状态。选择历史不会启动抓包；列表标为“历史抓包”，加载完成显示“已加载”。点击“返回当前抓包”回到运行任务；若正在查看的旧记录被自动删除，也会返回当前任务，没有运行任务则显示空状态。
清理仅操作本工具登记的独立抓包目录，不删除安装包、应用数据、设备配置、证书或 VPN 设置。目录异常或删除失败会保留该记录并写入后台日志，下次启动或抓包结束时重试。

`200` 只表示服务端返回成功状态，不保证响应一定有业务正文。“暂无响应”表示当前抓包链路
没有捕获到响应，不能把它当作空 JSON 或伪造成功数据。

点击“清空列表”只会隐藏当前已经显示的接口，不会停止抓包，也不会删除原始文件。继续操作应用后，新的接口仍会实时出现。搜索无结果时可更换 URL、Host、Path、方法或状态码关键词。

列表上方的“仅看接口”按钮可隐藏图片、音视频、字体、脚本、样式、普通网页及已识别的统计/系统检查请求，并显示已过滤数量。默认显示全部；再次点击关闭筛选，会恢复全部未清空的记录。关键词搜索可与此筛选叠加，新请求也会按当前筛选显示；切换不会停止抓包或删除记录。

这是基于请求类型和网址的启发式筛选，不是按应用进程精确归属。失败、暂无响应或类型未知的可能业务请求仍保留，避免漏掉排错线索；无法识别的后台请求可能仍出现。若找不到预期接口，先关闭“仅看接口”并清空搜索。旧版iPhone记录缺少响应类型时，只能依据已有网址等信息判断。

### 6.1 请求与响应断点

新版在接口页提供“设置断点”“断点规则”和“待处理”入口。先开始正常抓包，选中目标接口设置精确规则，点击“保存并启用断点”，然后在设备重新触发请求；暂停后可修改参数或响应，也可原样继续或终止。断点默认关闭，不会自动重放历史接口。

完整步骤及超时、正文限制、敏感信息与恢复方式见 [断点使用说明](breakpoint-user-guide.md)，下载 ZIP 内也提供同内容的 `BREAKPOINTS.md`。响应阶段服务器已执行请求，终止或改响应不能撤销业务操作。接口列表的清空、搜索和筛选不会取消待处理断点。

## 7. 查看日志

左侧“日志”用于实时查看当前应用的运行日志、系统日志和崩溃信息，可切换三种来源：

- `应用`：按当前 App PID 过滤。App 重启后会自动等待并连接新 PID。
- `系统`：查看设备主 Logcat 缓冲区。
- `崩溃`：查看 crash 缓冲区。

进入页面后，工具会自动发现正在运行的模拟器，以及已经通过当前 Mac 授权的 Android 真机。USB 真机需先在手机中开启“开发者选项 -> USB 调试”，连接数据线并在手机弹窗中允许此 Mac 的调试指纹；无线真机需先开启“无线调试”，完成与此 Mac 的 ADB 配对和连接。授权或重新连接后点击“刷新设备”，再从“Android 设备”中选择对应真机。

真机 Logcat 不要求 Root、Frida、Google 登录、证书或代理配置。应用日志会自动跟随当前真机前台应用；系统和崩溃日志无需先打开应用。部分正式版应用会关闭或裁剪自身调试输出，这是应用构建配置造成的限制，不代表设备连接失败。

页面支持“暂停显示、继续显示、清空日志、复制全部”、标签/消息搜索、级别过滤和自动滚动。
“清空日志”只清空当前内存视图，不会删除设备原始日志。日志最多保留 5,000 条或 2 MB，
只存于本机内存；切换设备、离开日志页或退出工具时会立即结束本工具启动的 Logcat 子进程，30 秒空闲回收仅作为异常退出兜底。

“真机日志”与“网络抓包”是两项独立能力：Logcat 不依赖真机实验抓包，也不要求替换 VPN。网络抓包默认使用模拟器；包含真机实验入口的构建可按第 14 节验证特定应用。

## 8. 运行检查

工具栏“运行检查”只展示四项摘要：本机环境、模拟器、网络、抓包组件。普通页面不会直接展示 Frida、ADB、端口、HTTP 状态或后端 JSON。

某项失败时先阅读“问题、原因、修复动作”。需要提供给开发人员时，再展开“技术详情”。如果端口被占用，工具会列出具体端口并停止启动流程，但不会自动结束占用端口的其他程序。

## 9. 数据与退出

运行数据保存在：

```text
~/Library/Application Support/AI抓包工具/runtime-native/
```

该目录可能包含 SQLite 数据库、APK 缓存、抓包文件、请求 headers、token 和后端日志。不要上传到
Git，也不要直接共享整个目录。升级 App 时保留该目录可以继续查看本机历史；删除该目录会清除
桌面端运行状态，但不会自动卸载 Android 模拟器中的 App。

停止抓包会停止 exporter、Frida hook 和 mitmproxy，并清理 Android 抓包代理。退出桌面 App 会
停止它自己启动的后端，不会终止本机其他项目的服务。若模拟器窗口仍在运行，可从 Android Emulator
正常关闭；禁止使用 `wipe-data`、`pm clear` 或无确认卸载来处理普通故障。

## 10. 常见问题

### Apple 无法验证“抓包工具”

这表示当前下载的是未经 Apple 公证的内部预览包，不是 Android 环境或抓包后端故障。只有确认文件来自本项目 GitHub Releases 且 SHA-256 校验通过时才继续。点击“完成”后，到“系统设置 -> 隐私与安全性”点击“仍要打开”。不要关闭 Gatekeeper，不要执行删除 quarantine 属性的命令。

### 内部服务启动失败

确认 7001 端口未被占用，并查看：

```text
~/Library/Application Support/AI抓包工具/runtime-native/native-backend.log
```

工具不会自动杀死占用端口的其他进程。

升级后首次启动时，桌面端会核对界面与内嵌后端是否属于同一构建版本。确认是本工具遗留的空闲旧后端时会自动接管并重启；旧版仍有抓包任务时会要求先停止任务；无法确认进程归属时会按普通端口冲突处理，不会结束该进程。

### 找不到 Android SDK

安装 Android Studio，或设置正确的 `ANDROID_SDK_ROOT`。确认 `adb`、`emulator`、`sdkmanager`、
`avdmanager` 均来自同一个 SDK 根目录。

### 模拟器启动或安装失败

等待 `boot completed`，在模拟器窗口完成解锁后重试。页面提示“当前抓包任务运行中”时，先停止
抓包再安装。签名冲突或降级安装不会通过卸载方式自动修复，以免清除登录态。

### 模拟器没有网络

先确认 Mac 本身可联网，再重新点击“开始抓包”。维护/登录阶段可使用宿主机代理；正式抓包前工具
会清空 Android 全局 `http_proxy`，避免 HTTP proxy 与 SOCKS 导流冲突。不要在抓包运行时手动设置
Android 全局代理。

### Frida 不可用

打开“运行检查”，确认使用的是工具准备的 Google Play 模拟器、设备已解锁且 Magisk/root
可用。Frida server 按设备端口隔离；不要手工启动另一个实例占用同一端口。

### 抓不到响应

先确认目标 App 在前台并实际触发了网络功能，再查看“接口”页和“日志”页。部分 App 使用证书绑定、
内置 CA、双向 TLS、QUIC 或自定义网络栈，可能只能捕获请求或完全无法解密。此时保留当前抓包代码和
抓包证据，再针对该 App 评估额外适配，不应把广告流量或 `200` 状态误判为目标业务响应。

状态长时间停留在“等待流量”表示链路已启动，但当前 App 尚未产生可导出的请求。先进入实际业务页
触发网络功能；不要仅凭首页静置 30 秒或自动滑动无结果就判定抓包失败。

## 11. 弱网模拟

在“抓包”页启动模拟器后，可以使用“弱网模拟”面板测试加载缓慢、请求超时和重试行为。无需先开始抓包，也可以在抓包运行中调整弱网。

1. 默认选择“不限制”，不会自动开启限速。测试时选择“2G”“3G”或“4G”。
2. 点击“应用弱网”，等待页面显示“弱网已开启”和实际生效参数。
3. 操作模拟器中的应用，在“接口”页观察 Request、Response 和请求耗时。
4. 测试结束后点击“恢复网络”，或选择“不限制”后点击“恢复网络”。确认状态变为“不限制”；恢复网络不会停止抓包。

上传、下载单位为 kbps（千比特/秒，不是 KB/s）；延迟单位为 ms，表示额外往返延迟。速率是每个网卡的共享上限，不是应用保证达到的速度；多个应用、TCP 重传、服务器速度和宿主机负载都会影响结果。

| 场景 | 上传上限 | 下载上限 | 额外往返延迟 |
| --- | --- | --- | --- |
| 2G | 128 kbps | 256 kbps | 600 ms |
| 3G | 512 kbps | 2048 kbps | 150 ms |
| 4G | 5000 kbps | 10000 kbps | 50 ms |
| 不限制（默认） | 不限制 | 不限制 | 不增加 |

这些档位是固定测试预设，不代表运营商标准，也不会改变模拟器显示的无线网络制式。选择后需点击应用才生效；“当前生效”显示设备已确认的参数。不限制会清除本工具的限速规则，不是设置一个较大的带宽值。

弱网会影响当前模拟器全部 Wi-Fi/移动网络流量，包括 Google Play 和登录请求，但不会改变 Mac 的网络、Android 全局代理或其他模拟器。建议完成 Google 登录后再开启。暂不提供丢包、抖动或断网场景，也不支持 Android 真机弱网。

需要本工具已完成环境准备的 Root 模拟器，以及支持流量整形的 Android 镜像。不满足条件或发现其他程序的网络规则时不会强行覆盖；可在面板的“运行检查”查看技术详情。

正常退出工具时会恢复网络，退出前最多等待 15 秒完成抓包和网络清理；异常退出或清理超时时，下次打开会根据恢复记录自动清理。模拟器离线时显示“等待恢复网络”，重连后自动重试。异常退出后请先重新打开工具并确认恢复，再删除本机运行目录，避免丢失清理记录。

如果“运行检查”提示规则归属无法确认，工具不会冒险删除其他程序的设置。关闭其他网络调试工具后重试；仍无法恢复时可正常重启模拟器，再打开工具检查。不要使用清除数据或卸载应用来恢复网络。

## 12. 卸载

1. 先停止活动抓包；如连接了 iPhone，先按第 13 节删除手机测试配置并结束连接，再退出桌面 App。
2. 删除 `/Applications/抓包工具.app`。若仍保留升级前的 `/Applications/AI抓包工具.app`，也可一并删除。
3. 如确认不再需要历史数据，再手动删除：

   ```text
   ~/Library/Application Support/AI抓包工具/
   ```

Android SDK、AVD 和模拟器中的 App 是独立资源，不会随桌面 App 自动删除。

## 13. iPhone 真机抓包

此功能不要求越狱或安装 Android SDK。连接验证通过后即可开始，不用创建项目或填写业务域名。
它记录由当前手机送入本工具的 HTTP(S) 请求，
不能判断某个请求一定属于哪个应用，也不保证所有 iOS 应用可抓包。已在原测试 iPhone 上验证
PokeHub、MelodyCraft、Wishly、StickerHub；2026-11-10还在新机iPhone_AA7（iOS26.5）通过桌面验证PokeHub业务HTTP200及完整Request/Response。
手机转发选择与恢复仍需手动操作。新增桌面导入入口已做隔离回归，但未用最终安装包在新机重复导入；不据此承诺所有设备或客户端版本。

### 13.1 前置准备与适用范围

- Mac：macOS 14+、Apple Silicon，安装本仓库新版预发布包；无需另装 Python、Android SDK、Frida、Xcode 或 iPhone 镜像。
- iPhone：已安装待测应用，允许本人安装测试描述文件并信任证书；无需越狱。不要求与 Mac 登录同一 Apple 账户。
- 网络：Mac 与 iPhone 连接可互通的可信 Wi-Fi。访客隔离、企业准入或局域网拦截可能使同名 Wi-Fi 下的设备仍不能互通。
- Mac 自身必须能访问待测服务；若应用依赖境外网络，应先确认 Mac 的出网能力。VPN 保持开启不等于仍从手机原节点出口访问。
- 下文已实测的是小火箭（Shadowrocket）专用 HTTP 节点统一接入；其他 VPN 客户端、新 Mac、新 iPhone 尚需分别验收。

首次准备一次后可跨应用复用。证书信任、手机转发和录制是不同步骤：安装证书不会自动抓包，连接通过也不会自动开始记录。

### 13.2 首次准备连接与证书

1. 让 Mac 与测试 iPhone 连接同一普通密码 Wi-Fi，确认设备之间可以互通。
2. 进入“抓包”，选择“iPhone”，点击“连接 iPhone”。Wi-Fi 名称能读取时自动填入，
   否则填写手机当前连接的完整网络名称，不要填写密码；企业账号认证网络不适用此配置。
3. 首次点击“准备连接”。工具选择本机地址和空闲端口，启动独立认证代理，生成一年有效的测试证书。
   私钥和认证信息长期保存在这台 Mac 的钥匙串中；同一运行目录下重连复用原证书、端口和认证信息。
4. 点击“发送配置到 iPhone”，通过隔空投送发送到自己的测试手机。新版默认发送仅含证书和检查入口的文件，不再要求运行终端命令。

新版小火箭流程的配置不包含 Wi-Fi、VPN 设置、代理密码或证书私钥，不会替手机切换网络。
使用小火箭时，保持 VPN 开启，下一步按13.3创建或复用专用节点，不必逐个添加业务域名。
这会暂时改变当前转发选择，但不需要覆盖原节点、订阅、DNS 或配置文件。仅在可信局域网测试。
不使用小火箭时，可展开“Wi-Fi 代理方式”使用原有含 Wi-Fi 代理的配置；不要同时使用两种方式。工具不读取 Wi-Fi 密码。

手机端必须本人完成：

若隔空投送找不到手机：在手机开启 Wi-Fi、蓝牙，保持解锁并靠近 Mac，到“设置 → 通用 → 隔空投送”临时选择“所有人（10 分钟）”，再在 Mac 选择准确的接收设备。新系统若要求隔空投送代码，在手机按提示获取并自行输入 Mac，不要发送到聊天；不要误选旧手机或他人设备。完成后恢复原接收设置。桌面发送区的“隔空投送找不到手机？”可随时展开查看。

更换新 iPhone 后需要在新手机单独安装并信任证书；本机复用证书不代表新手机已验证。桌面连接页的“使用小火箭时”会提示切换前记录原节点/路由模式，以及停止后手动恢复；工具不会替手机自动恢复。

1. 接收文件，在“设置 → 通用 → VPN 与设备管理”安装“抓包工具 iPhone 测试配置”。
   如系统要求设备密码，只在手机上输入。小火箭方式若显示 Wi-Fi 或 VPN 载荷，请取消并核对文件。
2. 在“设置 → 通用 → 关于本机 → 证书信任设置”，开启桌面引导中显示的
   `Capture iPhone Test …` 证书完全信任。核对本次证书名称，不要信任其他证书。
3. 继续下节配置手机转发，再打开“检查抓包连接”。不要在转发尚未接通时反复重装证书。

手动安装证书后仍需另行开启SSL/TLS信任，参见[Apple官方说明](https://support.apple.com/zh-cn/102390)。

连接验证不会自动记录应用接口。Mac 自检成功也不等于手机检查成功，仍需完成上述手机步骤。
旧版“抓包工具 iPhone 临时配置”的证书和 24 小时移除期限不能自动延长：首次迁移先恢复手机网络、
移除旧配置并在桌面结束旧连接，再安装和信任新版证书一次。不要删除原 VPN 配置。

### 13.3 小火箭首次设置与统一接入

#### 优先尝试桌面导入

本节对应包含“导入抓包节点”的新版源码；旧安装包没有该入口时需同步更新桌面和本机服务。本轮改动不代表 GitHub 安装包已发布。

1. 保持桌面“准备连接”成功，找到连接说明中的“3. 导入抓包节点”。
2. 手机通过 USB 连接并信任这台 Mac 时，选择“接收手机”，点击“导入抓包节点”。多台有线 iPhone 时必须明确选择，不会自动向旧手机发送。
3. 桌面优先尝试打开指定手机的小火箭导入确认。手机核对后确认新增 Capture-Mac；桌面提示“请求已发送”不等于已添加，也不等于连接已通过。它不会自动选用节点、切换路由或开关 VPN。
4. 缺少开发工具、USB 授权、客户端或请求失败时，会提供手动回退。无需为了基本抓包安装 Xcode：展开“未出现导入确认？查看手动方式”，使用下方当前参数新增，或通过小火箭扫描入口扫描节点二维码。
5. 已有 Capture-Mac 时先核对参数，不重复导入。只更新本工具专用节点，不覆盖原 VPN 节点。二维码和密码包含本机代理凭据，不要截图分享、粘贴到聊天或提交仓库。

#### 首次添加节点

1. 在小火箭首页记下原节点名称和“全局路由”模式，作为恢复依据。不要导出订阅或配置文件。
2. 已完成上述导入时无需再手动新增；导入失败时点小火箭右上角“＋”，类型选择 **HTTP**（不是 HTTPS 或 SOCKS5），地址、端口、用户名、密码使用桌面本页最新参数，备注填 `Capture-Mac`，其他项保持默认后保存。不要照抄别人的地址或密码。
3. 保持 VPN 开启，点选 `Capture-Mac` 名称行（不是右侧详情按钮），将“全局路由”临时设为“代理”。不编辑原节点、订阅、代理分组、DNS、FINAL 或原配置文件，不逐个添加域名，不开启小火箭自身的 HTTPS 解密。
4. 这条路径不依赖额外的 Wi-Fi 手动代理；不要叠加旧抓包代理。若此前为本工具手动设置过 Wi-Fi 代理，记录并恢复其原状态；不要更改公司必需的网络设置。如果测试描述文件新增了网络代理，退出前也必须检查恢复。
5. 打开手机桌面的“检查抓包连接”，或用手机扫描桌面二维码。该测试网址由 Mac 代理响应，未接通时 `capture-check.invalid` 可能提示网址无效，不是普通公网网站，也不需要添加公共 DNS 记录。
6. 手机显示“连接检查完成 / HTTPS 已通过”，且桌面显示“iPhone 已连接，尚未开始抓包”，才进入下一节。

这是临时统一转发，不是沿用原节点出口的多级代理。经 Mac 转发的连接使用 Mac 出网路径，出口 IP 可能变化。
不使用小火箭的普通 Wi-Fi 代理路径也需手机HTTPS实测；不能据此说明承诺任意其他VPN都支持。

#### 换电脑或手机，要不要修改 IP 和端口？

| 场景 | 处理方式 |
| --- | --- |
| 只换 iPhone，Mac 与网络不变 | 通常沿用同一服务器地址、端口和凭据；新手机仍需安装并信任当前 Mac 证书、导入节点和实际验证，不能沿用旧机验证结果。 |
| 换一台 Mac | 用新 Mac“准备连接”生成的地址、端口和凭据，安装并信任新 Mac 的证书；不要复制私钥。新电脑的地址、端口不保证相同。 |
| 同一 Mac 换 Wi-Fi、IP 改变 | 重新准备连接，刷新并更新 Capture-Mac 当前参数；同一有效身份的证书无需重新信任。 |
| 同一 Mac 重启工具 | 同一身份优先复用端口、证书和凭据；仍以当前界面显示为准。端口被占用时提示处理，不会擅自改端口或结束其他程序。 |

IP 是电脑在局域网中的地址，不是手机 IP。无论是否更换设备，手机与 Mac 必须可互通；导入成功、同名 Wi-Fi 和 VPN 开启都不能替代 HTTPS 检查。

### 13.4 开始抓包与查看接口

1. 确认页面显示“iPhone 已连接，尚未开始抓包”。无需选择应用项目或填写域名。
2. 点击“开始抓包”，再在 iPhone 中打开待测应用并操作，触发需要分析的请求。
3. 打开“接口”页，选择对应 iPhone 抓包记录，搜索完整 URL 并查看 Request、Response 和 cURL。
   “清空列表”仅清空当前显示，不会停止抓包。
4. 点击“停止抓包”只停止记录，连接仍保留并透传网络。再次点击“开始抓包”会创建新记录，
   在同一次有效连接内无需重新安装配置或信任证书。

新桌面流程不会按应用或域名过滤录制；搜索仅影响显示。可能同时看到手机后台请求，因此测试期间不要
操作无关敏感应用。仅有检查页通过不代表所有应用都已接入：如果手机VPN只转发部分域名，本工具仍无法
看到其余流量，取消桌面域名限制不会自动修改手机VPN。原节点、订阅和路由不会被工具改写。
旧客户端传入项目的API保持原有范围，历史项目和结果不会删除。Android 与 iPhone 的结果按来源分开；
“安装应用”“日志”和弱网仍仅用于 Android。

每轮最多 10,000 条或 500 MiB，到达上限后停止记录并保留透传。正文每段最多保存 8 MiB，
界面预览最多 256 KiB；被截断或尚未完成的请求不能生成完整可重放 cURL。已保存的 iPhone 记录和正文
重启后仍可查看，但不会自动恢复抓包；异常中断的任务会标为失败，而不是继续显示运行中。

应用不走系统代理、使用证书绑定、自定义加密或其他网络协议时可能无法捕获。
不要通过忽略证书校验、越狱或卸载应用来处理。测试期间不要操作银行等无关敏感应用。
所有抓包结果仅存于本机，分享前需移除 Token、Cookie、账号等敏感信息。

### 13.5 日常使用与恢复网络

前提是已完成首次准备。同一Mac/手机不用重复安装证书，不用为每个应用创建项目或域名规则。

1. 打开桌面，进入“连接 iPhone”，需要时点“重新连接 iPhone”。在小火箭首页记录当前“全局路由”模式和顶部显示的原节点名称，留作恢复依据。
2. 保持 VPN 开关开启，点选已有 `Capture-Mac` 节点名称（不是右侧详情按钮），将“全局路由”临时设为“代理”，完成手机HTTPS检查。
   不编辑节点参数、订阅、代理分组、DNS、FINAL 或原配置文件。
3. 在桌面端点击“开始抓包”，打开待测应用。按应用依次开始、停止，可将测试结果分成不同记录；
   同一轮也可能包含后台和 SDK 请求，不能把记录条数等同于该应用的独有接口数。
4. 测试完成或失败时，先点击桌面“停止抓包”，再在手机恢复第 1 步记录的路由模式和原节点。
   VPN 保持开启，确认普通网页可联网后，才退出桌面端或结束连接。

这是一种临时统一接入方式，不是沿用原节点出口的多级代理。经 Mac 转发的连接使用 Mac 的出网路径，
出口 IP 可能变化；Mac 必须能访问待测服务。录制范围不按应用或域名限制，期间不要操作无关敏感应用。
HTTP(S) 以外的协议、证书绑定和自定义加密仍不保证能读取；不能据三款应用的成功推断所有应用都支持。
桌面“停止抓包”只停止记录，不会自动切回手机节点；Mac 退出或断网前必须先恢复手机选择。

### 13.6 复用、换设备与撤销

- **暂时停止记录**：点击“停止抓包”，代理继续透传；不删除证书，不需要重新配置。
- **退出桌面端**：停止代理并删除运行目录中的临时密钥副本，钥匙串身份保留。退出前停用本工具专用
  测试路由、恢复曾手动设置的 Wi-Fi 代理，原 VPN 保持开启；电脑不能自动替手机恢复网络。
- **再次使用**：进入“连接 iPhone”，点击“重新连接 iPhone”，启用本工具测试路由，再打开手机的
  “检查抓包连接”。已安装并信任当前证书时不需要重装；检查通过后自行点击“开始抓包”。
- **彻底停止使用**：先停用本工具测试路由、恢复 Wi-Fi 手动代理，删除手机上的测试配置，确认联网正常。
  然后点击“结束连接并移除授权”，确认“已恢复手机网络，结束连接”。这会删除本机钥匙串身份，
  下次需要新证书及手机确认。不删除已有抓包结果，不停止 Android 抓包，也不删除原 VPN。

证书自首次创建起有效 365 天，重启不续期，描述文件按证书的绝对到期时间移除；不会隔天自动换证书。
到期、换 Mac、钥匙串身份丢失或主动撤销后，需要重新安装和信任。删除运行数据也可能使身份无法复用。
不要依赖到期移除恢复网络，尤其手动设置的代理和小火箭规则不会随描述文件删除而恢复。

切换小火箭的普通节点无需更换抓包证书，但它可能改变请求是否经过 Mac。统一接入期间应保持
`Capture-Mac` 为临时选择；恢复原节点后不能假定其余流量仍会被记录，下次测试重新按 13.5 接入。
不要把临时抓包选择当作长期上网配置。Mac 地址或 Wi-Fi 改变时，保留证书，更新本工具专用节点地址/网络设置即可。
原端口被占用时工具会报错，不会杀进程或悄悄改端口。
若提示钥匙串不可用，先解锁 Mac 后重试，不要反复删除手机证书。

新手机需要单独安装并信任证书、配置本机节点和完成检查；当前按一台连接手机录制，不承诺多台同时抓包。
换Mac需重新准备并信任新Mac证书；仅Mac地址变化通常保留有效证书，更新专用节点地址并重新检查。

### 13.7 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 检查页网址无效或无法连接 | 保持桌面开启，核对同网互通、当前Capture-Mac参数以及临时“代理”选择；不要只凭Wi-Fi名称判断互通，也不要继续重复安装证书。 |
| 提示代理鉴定 | 核对本机当前生成的用户名/密码，不用旧会话或别人给的示例；不要将节点设成无认证。 |
| HTTPS证书错误 | 核对桌面证书名称和手机“证书信任设置”，只信任本人本机生成的证书；不要忽略Safari安全警告。 |
| 检查通过但没有业务接口 | 桌面是否已点开始、手机是否仍选Capture-Mac＋代理、应用是否实际触发请求；检查页成功不等于每个应用都支持。 |
| 出现其他应用或SDK接口 | 统一转发可能包含后台流量；可搜索过滤，分应用开始/停止记录，不宣称按进程精确归属。 |
| Mac退出后手机无法联网 | 恢复测试前的原节点、原路由和Wi-Fi代理，VPN保持开启；停止桌面记录或删除证书不会替手机恢复这些选择。 |
| 隔空投送未发现手机 | 解锁手机、靠近Mac，核对Wi-Fi/蓝牙及临时接收设置；本人接收安装后恢复原接收范围，不为此退出Apple账户或改VPN。 |

如网络恢复后仍不能连接，先保留原上网配置，使用“运行检查”定位；不要删除手机应用、原VPN、订阅或全部设备数据。

## 14. Android 真机抓包（实验）

**操作路径：抓包 → Android → 真机（实验）。** 只使用 Android 手机时，不需要启动模拟器。

> 开始前请确认：本模式会临时替换手机当前 VPN，而不是让两个 VPN 同时运行。仅目标应用进入抓包隧道，其他应用不被采集，也不再由原 VPN 保护。测试期间不要操作无关敏感应用。原节点、订阅和配置不会被编辑；测试出口 IP 可能与原节点不同。

### 14.1 先确认是否适用

- 仅用于本人获准测试的应用。不需要 Root，不改源码、APK 或原应用数据，本流程不要求安装测试 CA。
- 当前是实验能力，不能保证所有应用、设备或接口均可解密。部分应用或系统更新后可能不再支持，请正常更新，不要降级或关闭安全更新。
- 本轮在一加 PHK110 上验证了 PokeHub、Wishly 的正式包与测试包，取得业务 HTTP 200 和完整 JSON；仍有其他连接解密失败。这不是所有版本或设备的兼容性承诺。
- 如果桌面没有“真机（实验）”，说明当前构建不包含此入口，不要改用模拟器步骤处理真机。本功能只作为开发预览提供，尚未完成全面验收。

### 14.2 首次使用：准备一次

| 准备项 | 需要做什么 |
| --- | --- |
| Mac | 使用包含连接助手的完整桌面构建；安装 Android SDK 的 platform-tools，确保 `adb` 可用。无需模拟器镜像、Java、Gradle 或自行编译助手。 |
| 手机 | 开启“开发者选项 → USB 调试”，用数据线连接 Mac，解锁后确认此 Mac 的 USB 调试授权。 |
| 网络 | 手机与 Mac 连接同一可互通的 Wi-Fi；开始前保持原 VPN 和节点不变，并确认目标应用能够正常联网。 |
| 应用 | 自行安装要测试的原版应用并完成登录。正式包与测试包分别验证，登录密码只在手机输入。 |

工具会复用 Mac 已有的 HTTP 上游代理，不修改系统代理；没有代理时使用直连。只有 SOCKS/PAC 的配置当前不支持，请根据提示检查，不要为了重试随意改动原网络设置。

### 14.3 每次使用：四步完成

1. **打开目标应用。** 连接并解锁手机，在手机中打开本轮要分析的应用，保持 USB 连接。多台手机在线时，先在桌面“使用手机”中选对设备；没有发现手机时点击“检测手机”。
2. **开始抓包。** 进入“抓包 → Android → 真机（实验）”，阅读并勾选实验授权，再点“开始抓包”。工具自动识别前台应用、准备连接参数、检查或安装连接助手。
3. **确认手机提示并查看接口。** 若手机提示安装“抓包连接助手”或创建 VPN，请本人确认。看到桌面“正在抓取手机应用”后，操作目标应用触发请求，点击“查看接口”，选择记录查看 Request 和 Response 的请求头、响应头及正文。
4. **停止并恢复网络。** 回到真机抓包页，点击“停止并恢复网络”。确认原 VPN 已连接、目标应用能正常联网后再结束；若出现“原网络尚未恢复”，按下一节处理。

**只有以下操作需要你完成：** USB 调试授权、系统要求的助手安装/VPN 确认、手机解锁与应用登录，以及自动恢复未成功时连接原 VPN。系统已经允许的操作不会要求每轮重复确认。

**工具自动完成：** 设备检查、前台应用识别、单应用范围校验、连接参数生成、启动抓包、保存接口与网络恢复检查。无需填写 IP、端口、业务域名，也无需手工导入 WireGuard 配置。

每轮只抓取开始时识别的一个包。需要换应用或在正式包/测试包之间切换时，先停止并完成网络恢复，再打开另一个包重新开始；仅切换手机前台页面不会自动切换抓包目标。

### 14.4 停止后：确认原网络恢复

1. 等待“停止并恢复网络”处理结束。停止录制与恢复原 VPN 是两个步骤，不能仅凭接口数量不再增加判断网络已恢复。
2. 如果显示“原网络尚未恢复”，保持原手机通过 USB 连接，在手机打开原 VPN 应用，使用原来的节点和配置恢复连接。不要删除、重建节点或导入其他配置。
3. 回桌面点击“检查网络恢复”。看到“抓包已停止，原网络连接已恢复。”后，再确认目标应用能正常联网。

目前 PHK110 实测仍需辅助连接原 Clash，不能承诺全部机型自动重连。连接助手可以保留供下次使用，正常停止并完成恢复后会清理本轮临时连接配置，不会开机自动抓包。

每轮最长 15 分钟。USB 断开或桌面失去响应时，助手设计为在停止续约约 20 秒后释放临时 VPN；这不等于原 VPN 自动恢复。请重新连接原手机，打开原 VPN 确认连接，再执行“检查网络恢复”。最终版本的真实拔线与授权未决取消场景仍待实机补验，不要主动拔线代替正常停止。

### 14.5 遇到问题时

| 看到的情况 | 下一步操作 |
| --- | --- |
| 未检测到 USB 真机 | 检查数据线、USB 调试和手机解锁状态，确认授权后点“检测手机”。当前不支持无线 ADB 抓包。 |
| 等待确认安装 | 在手机确认安装“抓包连接助手”；若需要锁屏密码，仅在手机输入。不要关闭系统安装保护。 |
| 误点 VPN“不允许” | 等桌面结束本轮处理，先确认原 VPN 仍连接；若提示恢复，先完成恢复。重新打开目标应用，再点“开始抓包”，在系统提示中点“允许”。无需卸载助手或清除应用数据。 |
| 等待手机授权但没有弹窗 | 查看手机是否锁屏或提示被其他页面遮挡；保持解锁。仍无法继续时先在桌面停止，完成网络恢复后重试，不要连续启动多个任务。 |
| 有请求，但没有响应正文 | 操作需要联网的页面后查看对应 Response。空正文、未收到响应和解密失败不是同一情况；HTTP 200 也不保证有正文，不要反复安装证书。 |
| 部分连接未通过 HTTPS 校验 | 该连接可能不支持实验解密。保留错误信息供排查，不降级应用、不关闭安全校验，也不要将其他成功请求当作该连接已成功。 |
| 原网络尚未恢复 | 按 14.4 节连接原 VPN，再点“检查网络恢复”。该手机恢复前不能开始下一轮；若已换机，使用“终止任务并重新检测”，旧机的恢复提醒会独立保留。 |
| 提示始终开启 VPN、工作资料、共享身份或助手签名冲突 | 当前条件不支持安全接管。不要关闭系统保护、卸载原应用或清除数据来绕过；记录提示后停止测试。 |

### 14.6 换手机、电脑或网络

先在原设备上停止抓包并恢复网络，再连接新设备重新开始。工具会生成本轮参数，无需沿用旧 IP、端口或手工复制配置。新的 Mac 需要重新获得手机 USB 调试授权；新手机可能需要确认助手安装和 VPN 授权。每台手机都应单独验证请求、响应和原网络恢复，不能沿用其他设备的成功结论。

**如果已经拔线换机：**

1. 在“Android → 真机（实验）”点击“终止任务并重新检测”。等待终止结束，工具会保留已抓取的记录并自动刷新 USB 设备。
2. 核对显示的是新手机，在手机打开目标应用，重新勾选实验确认后点击“开始抓包”。工具不会因为检测到新手机就自动开始，也不会将旧机的恢复操作发给新机。
3. 旧手机未确认恢复时，会保留在“待恢复的手机”中，关闭或重开桌面不会消除提醒。稍后连接这台原手机，打开原 VPN 恢复连接，再点它对应的“检查网络恢复”。原手机未连接时按钮不可用。

“任务已终止”只代表本机任务和代理已结束，不代表离线手机的原 VPN 已重新连接。旧手机临时连接依靠租约超时释放；请在该手机确认原网络正常后再使用其他应用。待恢复状态仅阻止对应手机再次抓包，不阻止另一台手机建立独立任务。

### 14.7 技术范围与数据保留

本模式使用独立连接助手的单应用 WireGuard 转发和独立 mitmproxy 运行时；实验解密依赖部分客户端存在的证书信任缺陷，并非通用免 Root 解密。独立证书锁定、修复后的客户端或不同网络栈可能拒绝连接。共享系统身份（shared UID）、工作资料及非主用户空间不支持接管。

历史记录沿用最近 7 次保留策略，超出的旧记录会自动删除，重要结果请及时留存。当前真机实验模式不提供弱网模拟、断点修改或 WebSocket 消息帧分析；不能直接套用模拟器的功能结论。

只看运行日志时使用独立“日志”页，不需要启动本节的实验抓包，也不需要替换原 VPN。
