# 独立可下载项目重构计划书

## 1. 目标

把当前内部使用的 AI 抓包工具重构为一个独立项目，其他用户可以下载到自己的电脑后，按文档完成安装、启动、设备配置和任意 Android App 抓包。

目标用户不应依赖当前机器、服务器、固定 AVD、固定包名或历史运行目录。项目默认运行在用户本机，通过浏览器控制抓包流程。

## 2. 核心交付形态

用户下载项目后，预期流程是：

```bash
git clone <repo>
cd <project>
./setup.sh
./start.sh
```

启动后打开：

```text
http://127.0.0.1:7001
```

页面完成：

- 环境检查：Python、Node、Android SDK、adb、emulator、mitmproxy、Frida。
- 设备发现：自动读取 `adb devices`，支持选择在线设备。
- App 管理：用户自己添加包名和 Activity，或从已安装 App 中选择。
- 抓包模式：支持 `system` 和 `flutter-socks`。
- 抓包查看：接口列表、请求详情、响应详情、cURL 导出。

## 3. 非目标

本轮不做以下事情：

- 不操作服务器，不改服务器上的任何文件。
- 不继续以 Mac mini / Jenkins / `192.168.77.150` 作为默认部署路径。
- 不默认绑定 MelodyCraft、`com.mi.ai.music`、`com.meta.inno.monopoly_sticker`。
- 不要求用户已有固定 AVD：`Medium_Phone_API_36.1`、`Capture_AVD_01/02/03`。
- 不实现 iOS 抓包，只保留未来扩展边界。
- 不重写 mitmproxy、Frida、ADB 底层抓包能力。

## 4. 当前问题

当前项目还保留了大量内部化假设：

- README 默认描述当前本机和保留模拟器。
- `capture_console/store.py` 内置固定设备池。
- `capture_console/runner.py` 内置 `emulator-5554` 和 `Medium_Phone_API_36.1`。
- 页面文案仍包含服务器、设备池、Google 登录、MelodyCraft 历史语境。
- 部署目录 `deploy/macmini` 是主线文档的一部分，容易让下载用户误以为必须部署服务器。
- 发布包脚本仍面向 Mac mini 部署，而不是通用下载包。
- `runtime/` 中包含本机运行数据、抓包历史、上传 APK、session 状态，必须从发布产物中隔离。

## 5. 推荐架构

保留现有三层架构，但重新定义默认边界：

```text
Browser UI
  -> FastAPI Console
    -> Device Discovery / App Registry / Capture Orchestrator
      -> adb / emulator / mitmproxy / Frida scripts
```

重构重点不是推翻现有实现，而是把“环境、设备、App、端口、代理”从硬编码迁移到本机初始化配置。

### 5.1 配置模型

新增本机配置文件：

```text
config/local.example.json
config/local.json
```

`local.json` 由初始化向导或 `setup.sh` 生成，不提交到仓库。

建议结构：

```json
{
  "console": {
    "host": "127.0.0.1",
    "port": 7001
  },
  "android": {
    "sdk_root": "",
    "default_mode": "flutter-socks",
    "auto_discover_devices": true
  },
  "capture": {
    "proxy_port_start": 9090,
    "web_port_start": 9091,
    "frida_port_start": 27042,
    "mitmweb_token": "android-capture"
  }
}
```

### 5.2 设备模型

默认不再写死 `device-1` 指向某个 AVD。

设备来源分两类：

- 自动发现：读取 `adb devices`，为在线设备临时分配端口。
- 手动配置：高级用户可在页面或配置文件中固定设备、端口和 AVD。

首版建议实现自动发现优先，手动配置作为高级入口。

### 5.3 App 模型

App 库默认为空。

用户可以：

- 手动输入包名和 Activity。
- 从设备已安装 App 列表中选择。
- 上传 APK 后自动解析包名和 Activity。

MelodyCraft 只能作为文档示例，不进入默认数据库。

## 6. 重构阶段

### 阶段 1：项目边界清理

目标：让下载用户看到的是通用工具，而不是当前内部项目。

工作项：

- 重写 README 首页。
- 新增 `setup.sh` 和 `start.sh` 作为通用入口。
- 保留 `start_capture.sh` 兼容，但文档主推 `start.sh`。
- 将 Mac mini / Jenkins / 服务器部署文档移入 `docs/legacy/` 或标注为高级历史方案。
- 更新 `.gitignore`，确保 `runtime/`、`config/local.json`、上传 APK、抓包历史不进入发布包。

验收：

- 新用户只看 README 即可理解本机安装流程。
- README 不再默认要求固定 AVD 或 MelodyCraft。

### 阶段 2：配置与初始化向导

目标：用户第一次打开页面，可以完成本机环境初始化。

工作项：

- 后端新增本机配置读取层。
- 页面新增首次使用向导：
  - 检查 Python/Node/Android SDK。
  - 检查 adb/emulator。
  - 检查 mitmproxy/Frida。
  - 自动发现在线设备。
  - 引导用户选择设备或启动 AVD。
- 初始化状态写入 `runtime/console.db` 或 `config/local.json`。

验收：

- 空 `runtime/` 状态下启动页面不会假设已有 `device-1`。
- 没有在线设备时页面显示明确下一步，而不是报错。

### 阶段 3：设备发现与端口分配

目标：去掉固定设备池默认假设。

工作项：

- 后端新增 `adb devices` 发现接口。
- 为在线设备自动分配 proxy/web/frida 端口。
- 检查端口占用，只拒绝冲突，不随意 kill 其他进程。
- 保留可选设备配置文件，支持高级用户固定端口。

验收：

- 任意在线 emulator 或真机都可以显示在页面上。
- 没有 `Medium_Phone_API_36.1` 也能进入主流程。

### 阶段 4：任意 App 抓包流程

目标：默认支持用户自己的 App。

工作项：

- 应用库默认为空。
- 从设备读取已安装包列表。
- 用户选择 App 后自动解析 Activity。
- 抓包启动前做 readiness 检查：
  - 设备在线。
  - App 已安装。
  - Activity 可启动。
  - Frida 可用或可准备。
  - 端口可用。
- `flutter-socks` 保留已修复的 no-force-stop 和长 pid 等待策略。

验收：

- 不依赖 MelodyCraft 也能启动抓包。
- 切换不同 App 不会因为测试包历史逻辑而失败。

### 阶段 5：发布包与清洁分发

目标：项目可以作为独立工具发布。

工作项：

- 新增通用 `release/package.sh`。
- 发布包包含：
  - `capture_console/`
  - `scripts/`
  - `web/dist/`
  - `config/*.example.json`
  - `requirements-console.txt`
  - `README.md`
  - `setup.sh`
  - `start.sh`
- 发布包排除：
  - `runtime/`
  - `.venv*`
  - `web/node_modules`
  - 本机抓包记录
  - 上传 APK
  - 服务器部署状态

验收：

- 解压发布包后，在另一台机器上可以按 README 启动。
- 发布包不包含历史 token、账号状态、抓包内容。

## 7. 测试计划

### 单元测试

- 配置读取默认值。
- 空设备状态。
- adb devices 输出解析。
- 端口自动分配。
- App Activity 解析。
- 发布包排除规则。

### 集成测试

- 空 `runtime/` 启动控制台。
- 无在线设备打开页面。
- 有在线设备但无 App 配置。
- 添加任意 App 后启动抓包。
- 停止抓包后进程和端口释放。

### 手工验收

- 新 clone 项目运行 `./setup.sh`。
- 运行 `./start.sh`。
- 打开 `127.0.0.1:7001`。
- 选择在线模拟器。
- 添加一个非 MelodyCraft App。
- 启动抓包并捕获至少一条接口。
- 导出 cURL。

## 8. 风险

- 不同用户的 Android SDK 路径不同，需要自动检测和手动覆盖。
- 真机与模拟器网络差异较大，首版应优先支持模拟器。
- Frida 依赖架构和 Android 版本，安装失败时需要明确错误提示。
- 某些 App 有证书绑定或 native 网络栈，无法保证一定可解密。
- Google 登录相关流量可能因忽略名单、系统组件或证书策略无法完整抓取。

## 9. 推荐实施顺序

建议先做最小可发布版本：

1. README 和项目边界清理。
2. `setup.sh` / `start.sh`。
3. 配置文件模板。
4. 空 App 库和空设备状态适配。
5. 自动发现在线设备。
6. 任意 App 添加与抓包。
7. 发布包脚本。

这样每一步都能独立验证，不需要一次性重写系统。

## 10. 完成标准

本轮重构完成后，应满足：

- 新用户不需要知道当前作者本机路径、服务器地址或 MelodyCraft 项目背景。
- 项目默认只面向本机运行。
- 页面可以从空状态开始配置。
- 任意 Android App 可以被添加为抓包目标。
- 发布包不包含本机历史数据。
- 文档能指导别人下载、安装、启动和完成第一次抓包。
