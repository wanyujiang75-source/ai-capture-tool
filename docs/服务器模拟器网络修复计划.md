# AI抓包工具：服务器隔离与模拟器网络修复计划 V2

## Summary

服务器版首先要保证“不影响 Mac mini 上已有项目”，其次才是修复模拟器网络和 Google 登录。V2 采用“隔离优先、只读预检先行、明确归属后再操作”的策略：所有端口、进程、代理、模拟器、Frida、mitmproxy 都必须绑定到设备池和项目运行目录，任何未知归属的端口或进程都只能报错，不能抢占、不能 kill、不能自动重启。

网络修复继续采用两种模式：`Maintenance Mode` 用于 Google 登录和应用维护，可使用宿主机代理；`Capture Mode` 用于正式抓包，必须清理 Android 全局代理并启动设备专属 mitm/Frida 链路。两种模式必须按设备隔离，不能影响其他设备，也不能影响服务器上的其他项目。

## Review Findings

- Mac mini 上存在其他项目，AI抓包工具不能假设端口可用，也不能按端口杀进程。
- 当前 `start_mitm_socks_stack.sh` 存在高风险行为：会直接 kill 占用 `PROXY_PORT/WEB_PORT` 的进程，必须修复。
- 当前设备端口默认值固定：`7001`、`19097/19098`、`9090/9091`、`9100/9101`、`9110/9111`、`27042/27142/27242`，部署前必须做端口占用预检。
- mitmproxy 默认监听 `0.0.0.0`，在服务器环境可能暴露代理给局域网其他机器，需要收紧或明确白名单。
- `127.0.0.1:7890` 这类宿主机代理属于外部服务，本项目只能检测和使用，不能管理、重启或关闭。
- 模拟器网络问题本质是 Mac mini 出口网络、Android 代理和抓包代理之间缺少模式切换。

## Goals

- 部署和启动前明确检查端口、进程、launchd、代理、AVD、ADB、Frida、mitmproxy。
- 严格区分本项目资源和其他项目资源。
- 任何未知归属资源冲突都阻止启动，并给出修复建议。
- 修复 Google 登录/Play Store 可用性问题。
- 抓包时自动切换到适合 `flutter-socks` 的网络状态。
- 停止抓包、释放设备、休眠时只清理当前设备相关资源。

## Non-Goals

- 不管理服务器上的其他应用。
- 不重启系统级网络服务。
- 不托管 Google 账号密码。
- 不自动安装或管理第三方代理软件。
- 不改 Frida、mitmproxy、exporter 的核心抓包逻辑。
- 不做公网部署方案。

## P0: Server Isolation First

### 资源归属原则

只允许操作以下明确归属的资源：

- `~/ai-capture-tool/current`
- `~/ai-capture-tool/shared/runtime`
- `~/ai-capture-tool/shared/config`
- LaunchAgent label：`com.ai-capture-tool.console`
- screen session 前缀：`ai-capture-*`、`mitmweb-<project-instance>-*`
- pidfile 中记录且命令行包含 `ai-capture-tool` 或本项目脚本路径的进程
- AVD 名称在设备池配置中的模拟器
- ADB serial 在设备池配置中的设备

禁止操作：

- 未知归属端口上的进程。
- 非本项目 launchd 服务。
- 非本项目 screen session。
- 系统代理/VPN/第三方代理进程。
- 不在设备池配置中的模拟器或真机。

### 端口预检

新增只读端口预检，检查但不修改：

- 控制台端口：`CONSOLE_PORT`，默认 `7001`
- 前端开发端口：`FRONTEND_PORT`，默认 `7002`
- 预览端口：`EMULATOR_PREVIEW_PORT`，默认 `19097`
- 预览 WebSocket 端口：`EMULATOR_PREVIEW_WS_PORT`，默认 `19098`
- 每台设备：
  - `proxy_port`
  - `web_port`
  - `frida_port`
- 外部代理端口：从 `CAPTURE_HOST_PROXY_URL` 解析，例如 `127.0.0.1:7890`

预检结果分类：

- `free`：端口空闲。
- `owned_by_project`：端口由本项目占用。
- `external_dependency`：端口由配置声明的外部依赖占用，例如宿主机代理。
- `occupied_by_other`：端口被其他项目占用，启动必须失败。
- `unknown`：无法判断归属，启动必须失败。

### 进程停止规则

停止资源必须满足至少一条：

- PID 来自本项目 pidfile，且命令行匹配本项目路径。
- screen session 名称匹配本项目命名规则。
- launchd label 等于 `com.ai-capture-tool.console`。
- ADB serial 或 AVD name 属于设备池配置。

禁止按端口无差别 kill。

### 监听地址规则

- Web 控制台可配置监听 `0.0.0.0`，但默认应在部署文档中明确仅限内网。
- mitmproxy 代理端口默认应优先监听 `127.0.0.1`；如模拟器需要访问宿主机，用 `10.0.2.2` 转发方案或明确配置可访问网卡。
- mitmweb UI 默认只监听 `127.0.0.1`。
- 预览服务必须有 token 或访问控制，不允许无鉴权长期暴露。

## P1: Network Modes

### Maintenance Mode

用途：

- Google 登录。
- Play Store 检查。
- 应用安装和首次启动。
- 用户手动完成 App 登录。

行为：

- 只允许在设备空闲、未抓包时启用。
- 可设置 Android 全局代理为 `CAPTURE_EMULATOR_PROXY`，例如 `10.0.2.2:7890`。
- 代理来源必须来自配置，不自动发现并启用未知代理。
- 如果宿主机代理不可用，只报错，不重启代理进程。
- 页面显示“维护网络模式”，避免误认为正在抓包。

### Capture Mode

用途：

- 正式 `flutter-socks + Frida + mitmproxy/exporter` 抓包。

行为：

- 启动抓包前必须清空 Android global `http_proxy`。
- 检查该设备专属 `proxy_port/web_port/frida_port` 可用。
- 如果端口被其他项目占用，直接失败。
- 启动 mitm/Frida/exporter 后记录 pidfile 和 session。
- 停止抓包只停止当前设备实例，不影响其他设备。

## P2: Network Diagnostics

### Host 检查

- 普通公网：`http://connectivitycheck.gstatic.com/generate_204`
- Google 登录：`https://accounts.google.com/`
- OAuth：`https://oauth2.googleapis.com/`
- Play API：`https://play.googleapis.com/`
- 可配置业务域名检查。

每个 URL 同时支持：

- direct 检查。
- host proxy 检查，前提是配置了 `CAPTURE_HOST_PROXY_URL`。

### Emulator 检查

- ADB 是否在线。
- Android 是否 boot completed。
- 是否已解锁。
- 默认路由。
- DNS。
- 当前 `settings get global http_proxy`。
- 能否访问普通公网。
- 能否访问 Google 登录域名。
- 能否连接 `CAPTURE_EMULATOR_PROXY`。

### Google 准入

- Play Store 是否存在。
- Google Play Services 是否存在。
- Google 账号是否已登录。
- 如果未登录，检查 Maintenance Mode 是否可用。

## P3: API Changes

新增 API：

- `GET /api/system/preflight`
  - 返回端口、进程、launchd、配置、外部代理、AVD、ADB 总体预检。
- `GET /api/system/network-check`
  - 返回 host direct/proxy 网络检查。
- `GET /api/devices/{device_id}/network-state`
  - 返回单设备网络状态。
- `POST /api/devices/{device_id}/network/maintenance`
  - 进入维护网络模式。
- `POST /api/devices/{device_id}/network/capture`
  - 进入抓包网络模式。
- `POST /api/devices/{device_id}/network/clear-proxy`
  - 清空当前设备 Android proxy。
- `POST /api/system/pause-project`
  - 停止本项目 Web/preview/抓包/模拟器资源，严格按归属规则执行。

现有 API 调整：

- `start device` 后刷新 network-state。
- `open-google-login` 前检查 Maintenance Mode。
- `start capture` 前强制执行 Capture Mode。
- `release/sleep` 只清理当前设备或设备池资源，不停止其他项目。

## P4: Frontend Changes

- 新增“服务器预检”区域：
  - 控制台端口。
  - 预览端口。
  - 每台设备端口。
  - 外部代理。
  - AVD/ADB。
  - 冲突说明。
- 设备卡片显示网络模式：
  - `维护模式`
  - `抓包模式`
  - `空闲无代理`
  - `异常`
- Google 登录按钮旁显示：
  - 直连可用。
  - 需要维护代理。
  - 网络不可用。
- 启动抓包时显示“正在切换到抓包模式”。
- 如果端口冲突，按钮禁用并展示占用进程摘要。

## P5: Script Changes

必须修改：

- `start_mitm_socks_stack.sh`
  - 删除按端口无差别 kill。
  - 只停止本项目 pidfile/screen 记录的实例。
  - 端口被未知进程占用时失败。
- `start_mitm_stack.sh`
  - 保持端口占用即失败。
  - 输出占用者摘要，便于页面展示。
- `stop_web_services.sh`
  - 增加项目归属校验，避免误杀同端口其他服务。
- 新增 `server_preflight.py`
  - 只读检查端口、进程、配置和归属。
- 新增 `network_diagnostics.py`
  - 只读检查 host/emulator 网络。

## Test Plan

### Unit Tests

- 端口空闲返回 `free`。
- 端口被本项目 pidfile 进程占用返回 `owned_by_project`。
- 端口被非项目进程占用返回 `occupied_by_other`。
- `start_mitm_socks_stack.sh` 不再 kill 非项目进程。
- 外部代理端口存在但不是配置端口时不归类为可用代理。
- Maintenance Mode 只修改目标设备 Android proxy。
- Capture Mode 清空目标设备 Android proxy。
- 有 active capture 时禁止启用 Maintenance Mode。

### Integration Tests

- Mac mini host direct Google 失败但 host proxy 成功时，网络状态为 warning，可进入维护模式。
- host proxy 不存在时，Google 登录入口提示网络不可用。
- device-1 进入维护模式不影响 device-2。
- device-1 启动抓包前清空 Android proxy，不影响 device-2 的 proxy。
- 端口被其他项目占用时，启动抓包失败且不 kill 进程。
- sleep/release 只关闭设备池中的模拟器。

### Manual Acceptance

- 服务器上存在其他项目监听端口时，AI抓包工具预检能发现并阻止冲突。
- 启动 Google 登录时能自动或手动进入维护模式。
- Google 登录完成后启动抓包，系统切换到抓包模式。
- 操作 App 后能抓到业务接口。
- 暂停项目只关闭 AI抓包工具资源，不影响其他服务。

## Rollout Plan

1. 实现只读 `server preflight`，不改变任何运行状态。
2. 修复危险脚本，移除无差别 kill。
3. 页面展示预检结果，端口冲突时禁用启动按钮。
4. 实现手动 Maintenance/Capture Mode。
5. 接入 Google 登录和抓包启动流程。
6. 最后增加 `pause-project` 严格归属停止能力。

## Operational Rules

- 服务器部署前必须运行 preflight。
- preflight 有 `occupied_by_other` 或 `unknown` 时禁止启动设备和抓包。
- 未配置 `CAPTURE_HOST_PROXY_URL` 时不启用维护代理。
- 任何自动停止操作必须写入日志，包含 device_id、pid、命令摘要和原因。
- 所有网络/代理操作必须以 device_id 为边界。
