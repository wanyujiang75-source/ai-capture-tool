# 抓包工具：安装与首次使用

本说明适用于从 GitHub Releases 下载的 macOS 桌面版。请只在已获授权的应用和设备上进行抓包或日志调试。

## 前置准备条件

### Mac 要求

- macOS 14 或更高版本。
- Apple Silicon 芯片（M1、M2、M3、M4 等）；当前版本不支持 Intel Mac、Windows 或 Linux。
- 使用 Android 模拟器时建议至少 16 GB 内存和 25 GB 可用磁盘空间。首次下载 Android 系统镜像时会占用数 GB 空间。
- 能访问 GitHub；使用 Jenkins 测试包时需要连接对应公司网络；需要 Google 登录时，当前网络必须能访问 Google 服务。

### Android 模拟器要求

- 新 Mac 需要先安装 [Android Studio](https://developer.android.com/studio)。至少启动一次 Android Studio，完成 Android SDK 初始化并接受 SDK License。
- Android SDK 至少需要 Platform-Tools、Android Emulator 和 Command-line Tools。抓包工具会优先复用现有 SDK，并自动安装或选择 Apple Silicon 原生的 Google Play 系统镜像。
- 默认抓包模拟器必须是 `arm64-v8a` Google Play 镜像。普通 AOSP 或仅 Google APIs 的镜像不能替代默认设备。
- Google 账号登录、模拟器屏幕解锁和应用账号登录必须由用户本人完成，工具不会保存或代填密码。

桌面包已经包含 Python、FastAPI、Frida 客户端和 mitmproxy 运行时，不需要单独安装这些组件。

### Android 真机要求

- 仅使用真机时需要 Android SDK Platform-Tools（adb），不需要模拟器镜像、Root、Java 或修改原应用。
- 使用 USB 数据线连接，解锁并允许当前 Mac 的 USB 调试；手机和 Mac 需在同一可互通 Wi-Fi。暂不支持无线 ADB、工作资料或共享 UID 应用。
- 进入“抓包 → Android → 真机”，在手机打开目标应用，阅读网络影响并勾选授权后点击“开始抓包”；助手安装和 VPN 授权由本人确认。
- 临时连接会替换原 VPN，而不是同时运行；仅目标应用进入隧道，其他应用不再由原 VPN 保护。原节点和配置不编辑，测试期间不要操作无关敏感应用。
- 结束时点击“停止并恢复网络”；若提示未恢复，在手机重新连接原 VPN，再点“检查网络恢复”。部分机型仍需手动连接，不承诺全自动恢复。
- 要取消整个流程或换机，点击“结束流程并重新检测”。记录保留，不会自动开始新抓包；旧手机离线时仍保留网络恢复提醒，不会操作新手机。
- HTTPS 解密依赖部分客户端的证书信任缺陷，不能保证所有应用或更新后的版本；入口简化不改变兼容性限制。不要求安装测试 CA，不应降级应用或关闭安全更新。每轮最长 15 分钟。
- 完整四步流程、拒绝授权后的重试和故障处理见包内 `USER_GUIDE.md` 第 14 节。授权未决取消、真实拔线和第二设备最终协议仍有实机验收缺口；本包仅为开发预览。

### iPhone 要求

- 仅使用 iPhone 抓包时不需要 Android Studio、Android SDK 或模拟器。
- iPhone 与 Mac 需连接同一可互通的普通密码 Wi-Fi；当前自动配置不支持企业账号认证网络。
- 需要本人在手机安装测试配置、完全信任本机测试证书；日常可复用，无需每次重装或删除。无需越狱、Root、Xcode、iPhone镜像或同一Apple账户。
- Mac本身须能访问待测服务；使用小火箭（Shadowrocket）统一接入时，VPN保持开启，但流量改经Mac出网，出口IP可能不同于原节点。其他VPN客户端尚需另行验收。
- 支持送入代理的 HTTP(S)，不保证证书绑定、自定义加密或其他协议可读；当前按一台连接手机录制，不保证多台并发。
- 已在同一测试iPhone验证PokeHub、MelodyCraft、Wishly、StickerHub的业务Request/Response；换设备仍需检查，不代表全部应用均支持。

## 安装步骤

1. 从同一个 GitHub Release 下载以下两个文件：
   - `AI-Capture-Desktop-<版本>-arm64.zip`，或带 `development-arm64` 的预览包。
   - 对应的 `.zip.sha256` 校验文件。
2. 在“终端”中进入下载目录并校验文件：

   ```bash
   cd ~/Downloads
   shasum -a 256 -c AI-Capture-Desktop-*.zip.sha256
   ```

   看到 `OK` 后再继续安装。
3. 双击 ZIP 解压，把 `抓包工具.app` 拖入“应用程序”。不要直接在 ZIP 预览窗口中运行。
4. 在 Finder 的“应用程序”中打开“抓包工具”。

当前 `development-arm64` 包使用内部开发签名。如果 macOS 提示无法验证开发者：

1. 在提示框中点击“完成”，不要点击“移到废纸篓”。
2. 打开“系统设置 -> 隐私与安全性”。
3. 在“安全性”区域找到“抓包工具”并点击“仍要打开”。
4. 使用 Touch ID 或 Mac 登录密码确认，再点击“打开”。

不要关闭 Gatekeeper，也不要使用命令删除应用的安全隔离属性。

## 首次使用 Android

1. 打开“抓包工具”，等待本机服务启动完成。
2. 进入“抓包”页并点击“启动模拟器”。新主机首次使用时，工具会检查 Android SDK、准备合规的 Google Play 模拟器并应用适合当前 Mac 的性能配置。首次下载系统镜像可能需要几分钟。
3. 如果页面提示 Android SDK、License 或系统镜像缺失，点击“运行检查”，按提示在 Android Studio 的 SDK Manager 中完成缺失项，然后重新尝试。
4. Android 启动后，在模拟器中手动解锁屏幕。目标应用需要 Google 服务时，先完成 Google 登录。
5. 安装待测应用：
   - 在“安装应用”页从 Jenkins 选择最新测试包；或
   - 点击“选择 APK”安装本地文件；或
   - 使用其他方式预先安装应用。
6. 在模拟器中打开需要分析的应用。工具会自动识别前台应用。
7. 回到“抓包”页点击“开始抓包”，然后在应用中操作需要分析的功能。
8. 在“接口”页搜索和查看 Request、Response 与 cURL；需要排查运行问题时进入“日志”页。
9. 完成后点击“停止抓包”，再正常退出桌面应用。退出桌面端不会关闭模拟器或清除应用登录状态。

Android 真机可以在授权 USB 调试或无线调试后读取“日志”，不要求 Root；当前桌面版的完整网络抓包流程仍以工具管理的 Android 模拟器为准。

## 首次使用 iPhone

### 1. 准备电脑与证书（首次）

让Mac和手机连接可互通的可信Wi-Fi。访客隔离或企业网络拦截可能使同名Wi-Fi也不互通；Mac需要能访问待测服务。

1. 在“抓包”页选择“iPhone”，点击“连接 iPhone”。确认或填写手机当前Wi-Fi名称，不要填写密码。
2. 点击“准备连接”，再点击“发送配置到 iPhone”。新版默认发送仅含证书和检查入口的文件，不改Wi-Fi/VPN，不再需要终端命令。隔空投送找不到手机时，展开桌面帮助，核对Wi-Fi、蓝牙、解锁、所有人10分钟及接收设备名称。
3. 在手机“设置 -> 通用 -> VPN 与设备管理”安装“抓包工具 iPhone 测试配置”。锁屏密码仅在手机输入；小火箭方式若含Wi-Fi/VPN载荷，请取消并核对文件。
4. 在“设置 -> 通用 -> 关于本机 -> 证书信任设置”完全信任桌面显示的 `Capture iPhone Test …`，只信任本机此次生成的证书，用于解密授权测试流量。

安装描述文件不保证覆盖已有Wi-Fi代理或VPN；使用小火箭时继续下面的专用节点步骤，不要因检查未通而反复安装证书。
证书手动信任入口参见[Apple官方说明](https://support.apple.com/zh-cn/102390)。

### 2. 导入抓包节点（首次）

在桌面“3. 导入抓包节点”选择接收手机，点击“导入抓包节点”，工具优先通过已信任的USB连接打开小火箭导入确认。请在手机确认新增；“请求已发送”不代表已导入或连接通过，不会自动选用节点、切换路由或开关VPN。

若自动导入失败，桌面会展开手动方式，显示本次服务器、端口、用户名、密码及节点二维码。可用小火箭扫描入口扫码，或按参数手动新增；基本抓包无需安装Xcode。已有Capture-Mac时只核对/更新该专用节点，不重复添加，不编辑原VPN节点。二维码和密码勿转发、截图分享或提交仓库，不要照抄其他电脑参数。

新手机、Mac和网络不变时通常沿用地址端口，但仍须在新手机安装信任证书并导入节点。换Mac时使用新Mac的地址、端口、凭据与证书；Mac换网络或IP改变时重新准备连接并更新节点，以桌面最新参数为准。同一有效证书不必因IP变化重装。完整操作见包内USER_GUIDE.md。

### 3. 小火箭统一接入（首次设置，以后复用）

1. 在小火箭首页记下原节点名称和“全局路由”模式，用于恢复。VPN保持开启。
2. 已完成导入时无需再新增；手动回退时点“＋”新增节点：类型 **HTTP**（不是HTTPS/SOCKS5），服务器、端口、用户名、密码用桌面最新参数，备注 `Capture-Mac`，其他项保持默认，保存。已有本机专用节点就只核对参数，不重复添加。
3. 点选 `Capture-Mac` 名称行，不点右侧详情；将“全局路由”临时选“代理”。不修改原节点参数、订阅、代理分组、DNS、FINAL或配置文件，不添加各应用域名，也无需开启小火箭自身HTTPS解密。
4. 这条路径不需要额外Wi-Fi手动代理，不要叠加旧抓包代理。此前专为本工具手动设置的代理应恢复原状态；不要擅改公司必需设置。若描述文件新增了Wi-Fi代理，退出前也须核对恢复。
5. 打开手机桌面“检查抓包连接”，或扫描桌面二维码。手机显示“连接检查完成 / HTTPS 已通过”，桌面显示已连接后继续。`capture-check.invalid`是本机代理处理的测试地址，不是公网网站；不通时先核对转发。

此方式不沿用原VPN节点出口，而是经Mac出网，出口IP可能改变。测试期间不要操作银行等无关敏感应用；后台HTTP(S)也可能进入记录。

### 4. 开始、查看与停止

1. 桌面点击“开始抓包”，再打开目标应用并操作联网功能。无需选择项目或填写业务域名；连接成功不会自动录制。
2. 在“接口”页选择本次iPhone记录，搜索URL并查看Request、Response、cURL。换应用无需重装证书；可按应用分别开始/停止以区分记录。
3. “清空列表”不停止抓包；“停止抓包”只停止记录并保留连接，不会自动恢复手机路由。已结束的历史记录按下文“更新与数据保护”的最近7次策略保留。
4. 测试完成或失败后，在手机恢复第3节记录的**原节点和原路由模式**，VPN保持开启；恢复曾为本工具改过的Wi-Fi代理，确认普通网页联网正常，才退出桌面或断开Mac网络。

当前录制不按手机应用进程隔离；统计数量可能包括SDK/后台请求。iPhone不支持桌面的安装应用、运行日志或弱网功能。

### 5. 下次使用、换设备与撤销

- 日常：桌面“重新连接 iPhone” -> 手机临时Capture-Mac＋代理（VPN开启）-> 手机HTTPS检查 -> 桌面开始抓包 -> 停止 -> 恢复原选择并验证联网。不会自动续录。
- 证书自首次创建起有效365天；私钥/认证保存在本机钥匙串，同一运行目录重启、隔天使用复用证书/端口/认证，重启不延长有效期。原端口占用时报错，不杀其他程序或悄悄改端口。
- 换应用或普通VPN节点不必换证书，但改变节点可能让流量不再经Mac；抓包时应保持Capture-Mac临时选择。新手机须单独安装/信任、设置节点和验证；不支持直接复制他人的配置使用。
- Mac地址或Wi-Fi改变：重新连接并核对专用节点地址；有效证书通常可复用。换Mac、身份丢失、主动撤销或证书到期：重新准备并在手机安装/信任。
- 彻底不再使用：先恢复网络，删除手机测试配置，确认联网后点“结束连接并移除授权”。本机会删除抓包身份，下次需要新证书。不要删除原VPN或订阅。
- 旧版24小时“临时配置”升级：先恢复手机网络、移除旧测试配置并结束旧连接，再安装信任新版一次。

退出或异常关闭桌面端不会自动恢复手机网络；删除描述文件也不会清除手动代理或小火箭选择。证书绑定、自定义加密、其他协议仍不保证抓取，不应忽略证书警告或要求越狱来绕过。

## 更新与数据保护

- **升级前请先备份重要抓包结果。** 新版启动后，以及每次抓包结束时，Android/iPhone合计仅保留最近7次已结束或失败的抓包；更早的记录及对应抓包文件会自动永久删除，不能从工具中恢复。正在运行的抓包不计入这7次，也不会被清理。
- 如需保留旧结果，请在退出旧版后、首次启动新版前，将下方运行目录复制到独立备份位置；不要将含Token、Cookie或账号信息的备份上传到公共位置。证书、设备配置、应用数据和未登记目录不属于历史清理范围。
- 升级前停止抓包并退出旧版，然后用新版 `抓包工具.app` 替换“应用程序”中的旧版本。
- 不要删除以下目录，除非明确需要清空全部本机数据：

  ```text
  ~/Library/Application Support/AI抓包工具/
  ```

- 该目录可能包含 APK 缓存、抓包文件和请求信息，备份或共享前应按敏感数据处理。
- 升级应用不需要删除 Android AVD，也不应执行 `wipe-data`、`pm clear` 或无确认卸载。

## 接口列表筛选

进入“接口”，点击列表上方“仅看接口”，可隐藏可识别的图片、音视频、字体、脚本、样式、普通网页及统计/系统检查请求。默认显示全部；关闭筛选即可恢复全部未清空的记录。筛选可与关键词搜索叠加，新接口继续实时显示，不会停止抓包或删除结果。

这是基于请求类型和网址的启发式筛选，不是按应用进程精确归属。失败、暂无响应和类型未知的可能业务请求仍保留；找不到预期接口时，先关闭筛选并清空搜索。“清空列表”仍只清空当前显示，新的接口继续出现。

## 请求与响应断点

带断点功能的新版在“接口”页提供“设置断点”“断点规则”和“待处理”入口。先正常开始抓包，再设置精确接口规则，点击“保存并启用断点”，然后在设备重新触发请求；暂停时可修改请求参数或响应，或原样继续。不开启断点时普通抓包不变，不需要为断点另装手机证书或修改 VPN。

完整教程在本 ZIP 的 `BREAKPOINTS.md`，请先阅读超时放行、敏感信息和大正文限制。响应阶段服务器已处理请求，终止连接不会撤销业务操作；“清空列表”也不会取消暂停项。不再调试时选择“全部保留原始内容并继续”关闭断点。

本轮已验证 iPhone 真机的只读请求参数和响应修改；Android 真机现场验收尚未覆盖，不能等同于所有设备、所有应用均兼容。

## 常见问题

### 无法启动模拟器

打开“运行检查”，确认 Android SDK、Emulator、Platform-Tools、磁盘空间和 SDK License 均正常。缺失组件应通过 Android Studio 的 SDK Manager 安装，不要删除已有 AVD。

### Google 登录失败

先停止正在运行的抓包，再检查 Mac 和模拟器网络。确保公司代理或 VPN 能访问 Google 服务；网络恢复后重新打开 Google 登录页面。工具不会读取或保存 Google 密码。

### 已打开应用但没有接口

Android：确认抓包页识别前台应用并显示正在抓取，在应用触发请求；必要时看“运行检查”。iPhone：确认已点击开始、仍为Capture-Mac＋代理且手机HTTPS检查通过，再触发业务请求；检查页通过不代表所有应用都可解密。

### iPhone 检查失败或退出后断网

网址无效/无法连接：核对桌面开启、同网互通、当前节点参数和代理模式。提示代理鉴定：核对本机当前用户名/密码，不关闭认证。HTTPS证书警告：核对本机证书完全信任，不跳过安全提示。退出后断网：恢复原节点、原路由和为本工具改过的Wi-Fi代理，VPN保持开启；不要重置全部网络或删除原VPN。

### 隔空投送收不到

将手机解锁并靠近Mac，核对Wi-Fi、蓝牙和临时接收设置；本人接收安装后恢复原接收范围。不需要退出Apple账户、配置iPhone镜像或关闭VPN。

### Jenkins 没有安装包

确认 Mac 已连接公司网络，然后刷新 Jenkins 列表。任务没有成功构建 APK 时，桌面端不会显示可安装文件。

### 日志数量很多

“日志”页默认会显示目标应用在 Android 系统中的实时输出。可使用级别、标签和关键词过滤；“清空日志”只清空当前显示，不会执行全局 `adb logcat -c`。

### 需要进一步诊断

在桌面端打开“运行检查”，先查看“本机环境、模拟器、网络、抓包组件”四项摘要，再展开技术详情。不要在公开渠道分享包含 Token、Cookie、账号信息或请求正文的诊断内容。
