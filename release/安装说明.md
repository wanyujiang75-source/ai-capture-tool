# 抓包工具：安装与首次使用

本说明适用于从 GitHub Releases 下载的 macOS 桌面版。请只在已获授权的应用和设备上进行抓包或日志调试。

## 前置准备条件

### Mac 要求

- macOS 14 或更高版本。
- Apple Silicon 芯片（M1、M2、M3、M4 等）；当前版本不支持 Intel Mac、Windows 或 Linux。
- 建议至少 16 GB 内存和 25 GB 可用磁盘空间。首次下载 Android 系统镜像时会占用数 GB 空间。
- 能访问 GitHub；使用 Jenkins 测试包时需要连接对应公司网络；需要 Google 登录时，当前网络必须能访问 Google 服务。

### Android 要求

- 新 Mac 需要先安装 [Android Studio](https://developer.android.com/studio)。至少启动一次 Android Studio，完成 Android SDK 初始化并接受 SDK License。
- Android SDK 至少需要 Platform-Tools、Android Emulator 和 Command-line Tools。抓包工具会优先复用现有 SDK，并自动安装或选择 Apple Silicon 原生的 Google Play 系统镜像。
- 默认抓包模拟器必须是 `arm64-v8a` Google Play 镜像。普通 AOSP 或仅 Google APIs 的镜像不能替代默认设备。
- Google 账号登录、模拟器屏幕解锁和应用账号登录必须由用户本人完成，工具不会保存或代填密码。

桌面包已经包含 Python、FastAPI、Frida 客户端和 mitmproxy 运行时，不需要单独安装这些组件。

## 安装步骤

1. 从同一个 GitHub Release 下载以下两个文件：
   - `AI-Capture-Desktop-<版本>-arm64.zip`，或带 `development-arm64` 的预览包。
   - 对应的 `.zip.sha256` 校验文件。
2. 在“终端”中进入下载目录并校验文件：

   ```bash
   cd ~/Downloads
   shasum -a 256 -c AI-Capture-Desktop-*.zip.sha256
   ```

   看到 `OK` 后再继续安装。
3. 双击 ZIP 解压，把 `抓包工具.app` 拖入“应用程序”。不要直接在 ZIP 预览窗口中运行。
4. 在 Finder 的“应用程序”中打开“抓包工具”。

当前 `development-arm64` 包使用内部开发签名。如果 macOS 提示无法验证开发者：

1. 在提示框中点击“完成”，不要点击“移到废纸篓”。
2. 打开“系统设置 -> 隐私与安全性”。
3. 在“安全性”区域找到“抓包工具”并点击“仍要打开”。
4. 使用 Touch ID 或 Mac 登录密码确认，再点击“打开”。

不要关闭 Gatekeeper，也不要使用命令删除应用的安全隔离属性。

## 首次使用

1. 打开“抓包工具”，等待本机服务启动完成。
2. 进入“抓包”页并点击“启动模拟器”。新主机首次使用时，工具会检查 Android SDK、准备合规的 Google Play 模拟器并应用适合当前 Mac 的性能配置。首次下载系统镜像可能需要几分钟。
3. 如果页面提示 Android SDK、License 或系统镜像缺失，点击“运行检查”，按提示在 Android Studio 的 SDK Manager 中完成缺失项，然后重新尝试。
4. Android 启动后，在模拟器中手动解锁屏幕。目标应用需要 Google 服务时，先完成 Google 登录。
5. 安装待测应用：
   - 在“安装应用”页从 Jenkins 选择最新测试包；或
   - 点击“选择 APK”安装本地文件；或
   - 使用其他方式预先安装应用。
6. 在模拟器中打开需要分析的应用。工具会自动识别前台应用。
7. 回到“抓包”页点击“开始抓包”，然后在应用中操作需要分析的功能。
8. 在“接口”页搜索和查看 Request、Response 与 cURL；需要排查运行问题时进入“日志”页。
9. 完成后点击“停止抓包”，再正常退出桌面应用。退出桌面端不会关闭模拟器或清除应用登录状态。

Android 真机可以在授权 USB 调试或无线调试后读取“日志”，不要求 Root；当前桌面版的完整网络抓包流程仍以工具管理的 Android 模拟器为准。

## 更新与数据保护

- 升级前停止抓包并退出旧版，然后用新版 `抓包工具.app` 替换“应用程序”中的旧版本。
- 不要删除以下目录，除非明确需要清空全部本机数据：

  ```text
  ~/Library/Application Support/AI抓包工具/
  ```

- 该目录可能包含 APK 缓存、抓包文件和请求信息，备份或共享前应按敏感数据处理。
- 升级应用不需要删除 Android AVD，也不应执行 `wipe-data`、`pm clear` 或无确认卸载。

## 常见问题

### 无法启动模拟器

打开“运行检查”，确认 Android SDK、Emulator、Platform-Tools、磁盘空间和 SDK License 均正常。缺失组件应通过 Android Studio 的 SDK Manager 安装，不要删除已有 AVD。

### Google 登录失败

先停止正在运行的抓包，再检查 Mac 和模拟器网络。确保公司代理或 VPN 能访问 Google 服务；网络恢复后重新打开 Google 登录页面。工具不会读取或保存 Google 密码。

### 已打开应用但没有接口

确认抓包页已经识别当前前台应用并显示正在抓取，然后在应用中执行会产生网络请求的操作。仍无数据时打开“运行检查”查看模拟器网络和抓包组件状态。部分应用的自定义加密或反调试机制可能需要单独适配。

### Jenkins 没有安装包

确认 Mac 已连接公司网络，然后刷新 Jenkins 列表。任务没有成功构建 APK 时，桌面端不会显示可安装文件。

### 日志数量很多

“日志”页默认会显示目标应用在 Android 系统中的实时输出。可使用级别、标签和关键词过滤；“清空日志”只清空当前显示，不会执行全局 `adb logcat -c`。

### 需要进一步诊断

在桌面端打开“运行检查”，先查看“本机环境、模拟器、网络、抓包组件”四项摘要，再展开技术详情。不要在公开渠道分享包含 Token、Cookie、账号信息或请求正文的诊断内容。
