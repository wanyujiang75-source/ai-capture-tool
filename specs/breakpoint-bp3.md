# BP-3 桌面断点契约与验收

## 边界

- 保留四导航；接口页规则入口、总开关、待处理入口，工具栏全局队列入口。搜索/筛选/清空/历史选择仅影响接口列表，不改变断点绑定。
- 一个桌面控制器绑定一个明确的正在录制目标；多录制时由用户选择，开启或仍有在途项时不换绑。绑定与 epoch 一起校验。重开桌面或换目标不自动启用。
- 自有后端启动设置 CAPTURE_BREAKPOINTS=1 以装载能力，引擎仍默认关闭；旧服务无能力则说明升级重启，不擅自重启。断点未启用时不改变抓包行为。
- 读取运行目录内本人所有、非链接、0600、<=4096B 的 breakpoint-desktop.json；认证 GET context 只返回目标身份，不下发 worker token/socket。拒绝非 loopback URL、重定向、超大响应。秘密只在内存，URL不带令牌。
- 本轮不操作真实设备、现有7001服务、系统代理、VPN、节点和原配置，不推送、发包或进入BP-4。

## 状态与编辑

- UI根级生命周期串行轮询，暂停页切换不停止续租。总开关/更新失败不会乐观显示成功。首绑先禁用遗留断点，原样释放，不恢复旧启用状态。
- 队列最多20条，摘要轮询不含正文；仅选中项加载<=1MiB控制帧。请求内容<=256KiB、200头/64KiB；草稿不落盘，切换/结束时清掉。超时基于后端剩余时长与本机单调时钟，不用跨进程deadline当墙钟。
- 编辑包含请求同源URL/方法、响应状态、重复有序业务头、文本/JSON/表单正文。敏感头默认遮盖，显式显示后才能编辑，不能提交遮盖占位符。受管协议头只读。
- 对照原始与草稿；仅发送修改字段；原样继续永不重编码。应用确认仅代表控制接受，不声称已送达；awaiting/applying/ended准确呈现，非法输入保留草稿和后端原期限。终止二次说明服务器动作不可撤销，不自动重试。
- 规则默认精确origin/path/method、下一次、30秒；可改前缀、阶段和15/30/60秒。规则模板最多100条/512KiB，以0600原子保存，仅含匹配条件，不含查询、认证、正文、目标或epoch；用户显式复用，结束或重启后不自动启用。
- 归档显示修改阶段/动作及原始/生效内容，不把采用当成送达；历史数据没有断点字段仍正常展示。

## 验收与证据

验收命令：swift test --package-path macos-native；python -m unittest tests.test_breakpoint_api tests.test_breakpoint_engine tests.test_breakpoint_archive；CAPTURE_TEST_BREAKPOINT_TRANSPORT=1 python -m unittest tests.test_breakpoint_integration；既有capture/ios/results回归。原生窗口使用新临时运行目录、独立loopback端口，绝不接入实际设备。失败/修复及最终证据如下。

首轮：Swift基线126项通过；新增5项模型/编辑、5项控制竞态通过，Swift全136项通过。context新增RED为405，补认证接口后9项API通过；归档预览RED缺body_text，补有界解压/哈希/拒绝链接后4项通过。真实Swift链路首跑请求修改成功，响应未暂停：隔离夹具重复添加Content-Type使其不满足候选正文类型，删掉夹具重复头后重跑，不修改产品准入以掩盖错误。首轮夹具SIGINT退出被uvicorn二次取消中断cleanup，补显式本地shutdown入口，后续使用该入口退出并核对自有worker清理。

复核与窗口修正：独立复核先发现发现列表阻塞心跳、失败后丢续租、可空端口解码、收集中换绑、加载标记残留，五项语义RED后全部修复。追加复核的启用后状态未返回就换绑、停用模板复用、详情失败无法重选、错误后迟到详情回写均新增RED；心跳拆成根级独立任务，不依赖status/pending/来源查询。窗口发现List内plain Button无法选择，改原生selection绑定后能打开请求/响应编辑；慢详情误报已结束、终止文案误报转发、503误报不支持分别RED/GREEN。

截至最终窗口复验：Swift152项7.071秒通过（其中1项live默认未运行，另以独立夹具显式执行1项0.203秒通过）；后端75项16.564秒、产品H1/H2真实链路45项121.176秒、既有抓包249项7.880秒通过。100MiB额外RSS：iOS 6,193,152B、regular 5,472,256B、SOCKS 5,947,392B，均保持原门槛。无底层传输代码修改；旧guard严格矩阵复用BP-2已记录结果，不声称本轮重跑。

原生窗口真实loopback证据：UI创建POST双阶段60秒规则、保存模板并重开复用；请求多行desktop_request/amount到达源站，响应改202和desktop_response正文到达客户端，真实结果content-length自动改64。非法JSON拒绝且草稿保留，原样继续不发送非法草稿；全部放行关闭断点；Cmd+A/C、删除、Cmd+V整块多行复制一致；终止取消与确认均操作。首轮UI耗时超过夹具90秒导致一个TimeoutError，实际双阶段允许2×60秒，夹具期限改150秒，不修改产品期限。当前7001只读核对仍be6d0543b498/running/idle/null，未操作手机、模拟器、VPN或原配置。

## 最终原生验收与收尾

- 原生工具栏与四导航保持正常；列表搜索无匹配、仅看接口、清空列表、切换主页面或查看来源后，全局待处理仍为1，原请求可继续编辑。启用/在途期间禁止换绑实际控制目标。
