# PokeHub独立副本免Root抓包试验

## 目标与边界

2026-11-06，任务ANDROID-COPY1。从指定一加d5f39352的Play原版com.mi.poketrade 2.1.0(96)提取APK集合，仅在Mac私有临时目录修改。新包名固定com.mi.poketrade.capturetrial，名称PokeHub 抓包试验。原包、数据、证书、VPN和原节点不改；不启用第二VPN、不调用root、不复制登录令牌或私有数据、不自动触发登录和业务写操作。

## 设计

保留原业务类和Flutter产物；为base和split统一更换安装身份，隔离provider authorities和自定义permission；应用入口加载arm64 Frida Gadget，监听回环地址和独立端口并要求临时认证。仅通过精确serial的独立USB转发访问组件。不把Gadget装入原版、VPN或系统进程。

优先复用已有进程内TLS与网络诊断脚本。需要中间代理时只改变副本进程的连接目的地，经USB至独立Mac代理，复用电脑现有出网代理；不更改手机系统代理/信任或VPN配置。采集限定目标业务，敏感正文仅本机私有临时目录，报告只给方法、路径、状态码、正文长度和脱敏结构。

新签名/包名可能破坏Google登录、深链和完整性校验，不能声称副本与线上包行为完全一致。不尝试伪造正式签名或绕过服务端身份校验。需要登录时用户手动完成。

## 单任务执行与验收

1. 记录原包路径、APK摘要/签名、VPN连通标记、系统代理、forward/reverse及本次目标包不存在。
2. 离线解包；修改安装身份和诊断入口，独立签名；校验所有split包名/版本/签名一致，authorities/自定义权限与原包不冲突。不得使用卸载、清数据或覆盖原包命令。
3. 安装副本，检查独立UID、标签、启动和Gadget认证连接。异常日志限副本进程、限时限量。
4. 对只读业务请求取得方法/路径/状态/真实正文才算抓包通过。登录前接口、浏览器对照和完整业务验收分别记录，不用日志URL或合成HTTP代替成功。
5. 停止副本自有诊断/代理及转发；复核原版APK摘要、VPN/代理和原forward。私钥/认证材料不入仓库，不发布修改APK。
6. 将证据与局限写回本文件和progress.md，git diff --check后本地提交。产品代码未改时不构建桌面或复用其测试宣称真机通过。
