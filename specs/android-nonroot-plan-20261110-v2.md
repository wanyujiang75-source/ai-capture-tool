# Android 真机免 Root 抓包实施计划书 V2

日期：2026-11-10。状态：修订计划，尚未实施。替代 android-nonroot-plan-20261110.md；技术依据为 android-nonroot-feasibility-20261110.md。

## 1. 交付目标与当前阻塞

目标是在用户现有未 Root Android 真机上，使用未修改的原版应用，在保留现有 VPN 的条件下获取并展示业务 Request/Response。PokeHub 是首要目标，StickerHub、MelodyCraft、Wishly 分别验收。

当前没有证据证明现有四个原版包具备满足全部约束的完整解密路径。计划不能把“做出能力检查界面”“捕获域名”“一个其他应用成功”作为 PokeHub 目标完成；不能承诺通过更换代理或证书必然突破。

交付分层：研究报告、指定应用技术原型、指定应用桌面能力、发行验收分别记录。部分应用通过只允许声明对应设备/应用/版本/路线支持，其他目标保持阻塞或未覆盖。研究任务 ANDROID-NR-RESEARCH 的现有 BLOCKED 不因本计划生成而解除。

## 2. 不变边界

- 不 Root、不解锁启动引导程序、不利用漏洞、不降低系统安全设置。
- 不改源码、APK、签名或安装态；不卸载、不清数据、不复制登录态。
- VPN 保持开启；原节点、订阅、规则、DNS、默认路由不改；不启动第二个替换既有 VPN 的 VpnService。
- 默认只读。不得自动安装 CA、辅助应用、设备管理配置或 Gadget。
- 后续临时网络变更或安装证书不在本计划的默认授权内；必须具有对应操作的明确授权和可验证恢复条件，不能复用旧试验的授权。
- 不从应用私有目录提取凭据。获准采集的业务报文可能包含鉴权信息，应与登录凭据提取区别处理：本机受控存储、界面默认遮盖、导出默认脱敏，不提交生产报文或密钥。
- 不改变现有 Android 模拟器、iPhone 抓包和断点协议；仅在独立模块接入已验证路线。

## 4. 技术路线与能力契约

只寻找原版已经具备的合法诊断入口、实际受信任的代理路径、合法导出的目标 TLS 会话密钥及授权服务端采集。当前均未取得可用的新入口，不预先选定实现路线。

| 路线 | 实时采集 | 正文读取 | 请求修改 | 响应修改 | 断点 |
| --- | --- | --- | --- | --- | --- |
| 原版诊断/日志出口 | 由出口实测决定 | 逐字段核验，不能默认完整 | 默认不支持 | 默认不支持 | 默认不支持 |
| 在线受信任代理 | 链路验证后支持 | 以真实业务完整性为准 | 需独立在线控制验证 | 需独立在线控制验证 | 需独立验证，解密不自动授予 |
| PCAP + 目标TLS密钥 | V1按离线导入处理 | 解密、重组成功后支持 | 不支持 | 不支持 | 不支持 |
| 服务端/网关日志 | 由出口实测决定 | 可能缺失或被处理，逐项记录 | 不支持修改手机原请求 | 不支持修改手机收到的响应 | 不支持 |
| 密文PCAP/CONNECT/连接统计 | 仅连接层，能否持续采集另验 | 不支持 | 不支持 | 不支持 | 不支持 |

每个适配器返回 independent capabilities：realtime_capture、body_read、request_modify、response_modify、breakpoint，各为 unknown/supported/unsupported，并附证据及适用范围。请求与响应正文完整度分别记录，不能将有一项能力泛化为全支持。

服务端记录必须标明采集位置和服务端视角；CDN、缓存、网关转换可能导致内容与手机实际收发不同，未经端到端核对不得等价为手机原始报文。离线模式显示“导入并分析”，不显示“正在实时抓包”。

当前免 Root 新路线默认关闭修改与断点入口；未来仅在相应能力独立验收后启用。模拟器和 iPhone 既有断点不受此默认值影响。

## 5. 首次验证、准入与缓存

### 5.1 分离技术可行性与会话准入

状态流：只读检查 checking → 候选成立 probe_available → 受控验证 probing → 正文证据通过 verified → 正式采集 recording → 停止 stopped。

其他状态：needs_action（有具体可处理缺项）、blocked（缺少当前权限/依赖）、unsupported（该路线已确认不适用）、recovery_required（自有资源或授权变更未恢复）。未知是证据状态，不直接等于 unsupported。

新设备进入 probe_available 不要求既有业务正文。条件是目标身份明确、有已验证机制的候选路线或研究原型、对应权限齐备、资源有界且不存在未恢复项。仅 ADB 在线或安装了 CA 不构成候选。

受控验证本身允许尝试接收目标应用业务请求；失败不能进入正式采集。产品路线第一次原型验证由 NR-2 完成，产品发布后的新设备再通过相同受控验证流程，避免依赖开发人员先为每台手机生成历史记录。

正式采集前重新检查身份与连接条件，要求当前验证证据有效。已验证会话可以继续接收不同接口，但新增域名/网络栈不自动视为已解密；失败单独标记，不能把全应用改为全部支持。

### 5.2 受控验证预算

默认最长120秒，最多20个目标业务事务；正文、内存、磁盘、并发连接沿用既有安全上限，并在NR-2核验实际数值后形成可配置常量。预算到达必须停止新增采集并报告未完成项，不把限额截断当完整正文。

默认只触发目标应用已授权的只读操作；不重放登录、支付、删除或其他写入请求，不用关闭证书验证换取成功。用户取消或超时后停止本轮自有资源，不影响原 VPN。范围无法确认或依赖变更未获授权时不启动验证。

### 5.3 身份与证据缓存

证据键至少包含：ADB目标标识、Android用户/工作资料ID、package、versionCode、当前签名证书SHA-256及可核验的签名轮换链、base APK与所有split APK的排序路径/名称及SHA-256、系统build fingerprint、适配器/采集引擎版本、路线类型。

连接绑定包含：当前ADB连接代次、代理实际端点、CA公有指纹或密钥导出来源身份、TLS终止点身份；不将密码、Token、CA私钥写入缓存。服务端权限失效也必须使对应证据失效。

摘要用于确认试验前后包没有变化；没有厂商可信签名/产物基准时，不能单靠本机摘要宣称原版来源已完全证明。Play安装来源只作线索。必要身份读不到时只允许只读检查，不允许带成功标签的正式采集。

证据仅本次后端进程有效，验证通过后10分钟内可用于首次启动；超时、设备断开/重连、应用更新/同版本重签、split变化、系统更新、端点或CA变化、身份读取失败、检测到VPN连接变化都回到检查/验证。当前任务持续运行不因10分钟到期被突然中断，期间若发现条件变化则停止新增采集并进入重新验证；后续启动不能复用过期证据。

无法读取 VPN 私有节点信息时明确标记不可观测，不声称核验了原节点。可观测连接变化后失效；检查期间及启动前核验本项目端点，运行时任何TLS失败不得沿用旧成功状态。默认不持久化可跨重启复用的成功授权。

## 6. 生命周期与异常恢复

验证和采集共用状态：idle → checking → probing/recording → stopping → stopped；任何清理未确认转 recovery_required。重新打开应用只显示状态，不自动继续抓包或重放旧命令。

默认路线不修改手机网络，因此异常时主要回收本项目子进程、监听、连接和USB映射。即使VPN仍在线，也不得把自有代理遗留误报为已恢复。

如未来另获临时变更授权，先证明有原值或可行的手动恢复路径，再执行。写前日志记录operation_id、owner、设备/用户、资源标识、授权范围、非敏感原值/安全引用、预期值和恢复步骤；日志先落盘再变更。密钥放受控密钥存储，不写普通日志。

停止及恢复必须幂等，只清理由本轮创建且身份匹配的资源；PID需结合启动时间/命令或控制句柄，不能仅凭端口/PID判断所有权。不kill其他进程，不覆盖外部后来修改的配置，不批量清空ADB映射，不删除用户既有CA。

| 故障 | 必须行为 | 验收证据 |
| --- | --- | --- |
| USB拔线/设备重启 | 停止新增采集，证据失效；不向其他设备发恢复命令 | 原目标隔离、重连需新验证 |
| Mac休眠/网络切换 | 唤醒后重新检查端点与证据；不自动延续旧成功 | 无静默续录、断链原因可见 |
| 后端或桌面崩溃 | 下次启动识别自有日志/孤儿资源，只做可证实安全的清理 | 不启动旧抓包、不误杀外部进程 |
| 代理或上游退出 | 及时标记失联并停止成功状态，不无限重试业务请求 | 无伪200/空正文成功，无重复业务写入 |
| 重复停止/取消与超时并发 | 单次所有权释放，重复调用安全 | 无僵尸进程或资源二次删除 |
| 恢复失败/设备离线 | 保留recovery_required和明确手动步骤，不删除恢复依据 | 页面与状态均不报恢复完成 |

若存在已授权手机变更而手机离线，无法保证立即联网恢复，必须在变更前告知风险并提供手机侧恢复步骤。用户未接受该风险时不走这条路线。不能将“先关掉Mac代理”当作手机网络恢复。

## 7. 阶段、文件范围与通过门槛

### NR-0：证据与首次验证契约

复用 capture_console/android_physical_capabilities.py、device_discovery.py、foreground.py。新增 capture_console/android_capture_admission.py 与 tests/test_android_capture_admission.py，定义身份、候选资格、生命周期和缓存失效，暂不写手机配置或启动真实代理。扩展 tests/test_android_physical_capabilities.py 覆盖只读边界。

先写新设备无历史证据、无候选、未授权、包变化、多个设备、断线、过期及恢复未完成的失败测试；再最小实现并验收。重点证明 probe_available 不依赖已解密证据，而 recording 必须有当前有效证据。

验收：ADB命令时长/输出有界；设备与用户精确匹配；未知不伪装成功；只读检测不执行root、settings put、安装、VPN切换；恢复信息不泄漏凭据。

### NR-1：验证新的正文出口假设

以前述调研为基线，不重复同条件的失败CA试验。每个新增候选必须列出新证据、需要的权限、接入方法、预期业务证明、失败停止条件和恢复方法。

优先查原版已有诊断出口；密钥路线需确认目标会话密钥确实可获得，服务端路线先确认权限与字段完整度。不采用改包、Root或关闭原VPN作为隐含后备。

1个工作日时间盒；没有满足约束的新候选就保持BLOCKED，停止后续产品化。已有AP-0事实直接复用，仅复核变化项，不重新以一轮诊断冒充突破。

### NR-2：隔离原型与真实原版验证

只在候选成立且有对应授权后开始。在独立目录运行单路线原型，不重启现用桌面端或改变现用抓包任务。资源状态与接口合同写入 specs/android-nonroot-prototype-contract.md，再实现对应隔离测试 tests/test_android_nonroot_prototype.py；这些为本阶段新建文件，不提前声明已存在。

先验证自有HTTPS夹具：JSON、表单、压缩、重复头、重复请求、空正文、错误、慢正文、256KiB/2MiB/20MiB正文。对照夹具预期字段、字节长度和归档摘要；区分原始编码、解压后展示和脱敏展示。夹具通过不等于原版通过。

原版必须至少捕获三个不同业务接口、一次重复请求和一次页面切换；请求/响应关联准确、头和正文可用、截断状态真实。至少一种业务对象与触发操作/应用显示结果对照，排除缓存记录或第三方SDK流量冒充业务请求。无法证明完整度的字段标记unknown，不报完整采集通过。

同时执行第6节故障矩阵。仅凭域名、握手、浏览器成功或部分日志不能通过。证书再次被拒绝且无新信任机制、必须提权/改包/改原VPN时立即停止，不叠加试错。

### NR-3：桌面端接入已验证路线

前提是NR-2指定目标实际通过；不是先做全部界面再等待技术突破。

复用既有正文有界预览、归档、历史保留和日志能力。新增 capture_console/android_capture_capabilities_api.py 负责只读检查/受控验证入口，生命周期实现复用NR-0模块；根据已证实路线增加一个适配器，不并行实现猜测路线。

桌面新增 AndroidCaptureCapabilityModels.swift、AndroidCaptureCapabilityView.swift，在既有APIClient.swift和抓包页接入；文案统一AppCopy。新增 tests/test_android_capture_capabilities.py、AndroidCaptureCapabilityTests.swift；新增 tests/test_android_capture_recovery.py 覆盖生命周期故障。

只读接口：GET /api/devices/{device_id}/capture-capabilities?package={package}，只返回状态和脱敏证据，不改变手机。受控验证为POST /api/devices/{device_id}/capture-probes，需严格身份/候选/授权/恢复状态校验，返回probe_id；GET同路径/{probe_id}查询、DELETE同路径/{probe_id}取消。探测不得通过GET隐式启动。

探测按设备/Android用户互斥，与已有抓包/安装任务冲突时给出原因，不擅自停止其他任务。关联证据与会话不得跨设备或包复用；取消、过期与启动竞争必须测试。

用户流程：连接手机 → 打开应用 → 检查条件 → 有候选则验证连接 → 通过后开始采集。无候选显示具体阻塞，不显示“正在准备”无限等待。离线导入与服务端视角使用不同入口/标签，不与手机在线代理混称。

### NR-4：多应用、本地整包与回归

PokeHub、StickerHub、MelodyCraft、Wishly逐一记录签名/摘要/版本、路线、正文证据与清理结果。第二台Android可用时再验证首次接入；无第二台则记未覆盖，不能宣称普遍兼容。PokeHub未通过时，该首要目标继续BLOCKED，即使其他应用成功也不改变。

完整性和资源验收包含大正文、慢正文取消、磁盘空间不足、断线及第6节全部故障；过大或受限内容必须显示截断/失败，不能伪造完整。离线日志或密钥路线不测其不具备的断点修改，但必须证明界面禁用。模拟器/iPhone既有断点独立回归。

本地整包构建、严格签名、内嵌后端隔离启动/退出、受限PATH、四主页面以及首次验证/失败/恢复状态是NR-3/NR-4必测，不依赖发布请求。不覆盖当前安装应用，不清除用户数据，使用隔离路径/端口；端口占用只报错。

## 8. 验收命令、证据与发布边界

实施时按阶段创建对应测试文件，再运行；本轮计划修订不运行以下构建或实机动作。

```bash
# NR-0
python -m unittest -v tests.test_android_physical_capabilities tests.test_android_capture_admission
# NR-2
python -m unittest -v tests.test_android_nonroot_prototype
# NR-3/NR-4
python -m unittest -v tests.test_android_capture_capabilities tests.test_android_capture_recovery
python -m unittest discover -s tests
swift test --package-path macos-native
macos-native/scripts/build-app.sh
codesign --verify --deep --strict macos-native/build/抓包工具.app
git diff --check
```

内嵌后端启动需按现有脚本在私有临时目录与空闲端口验证，检查实际build ID、Python依赖、自有进程退出和资源释放，不复用用户当前7001端口。新增隔离生命周期测试纳入 tests/test_android_packaged_lifecycle.py；失败不能以源码单元测试通过抵消。

受控证据目录仅本机当前用户访问，记录大小和到期时间并支持清理；对外仅脱敏摘要。TLS密钥按凭据管理，不写仓库、公开日志或截图；诊断报告不能包含订阅、原节点密码、Token或生产正文。

将最终结果分为：通过、明确不适用、技术阻塞、未覆盖。测试通过只证明各自范围，报告不使用“所有原版免Root通用解密”等未证实表述。

远端推送、合并、GitHub Release和下载包上传仍需用户相应请求；不能因此延后本地构建验收。正式发布另外检查打包指南、架构、摘要、签名及对外支持矩阵，不将当前预览包称为已公证正式发行版。
