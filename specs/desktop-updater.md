# macOS 桌面更新

当前用户使用的原生 SwiftUI App 在应用菜单提供「检查更新…」。旧预览版手动安装首个正式版，之后手动检查，由 Sparkle 展示版本、下载进度和确认。关闭定时检查和自动安装。保留手动下载路径。

- 使用 SwiftPM 锁定 Sparkle 官方二进制版本。手工打包时把 Framework 和必要辅助程序放入 App，签名后执行严格签名验证。正式包使用现有 Apple Developer ID 公证路径。
- 正式版使用 `TRACEDECK_VERSION` 和显式递增的 `TRACEDECK_BUILD_NUMBER`。保持 bundle ID 和原数据目录，正式包内置更新公钥及 GitHub 正式 Release 的固定 HTTPS appcast URL。开发预览包沿用手动分发。
- 菜单检查与安装确认前都检测正在执行的本地操作、手机恢复标志和对应内嵌后端的活跃会话。查询失败时提示稍后重试或手动安装。更新期间暂停桌面操作，取消后恢复可操作。保留已有退出与重启流程。
- 正式分发生成现有手动安装 ZIP 和独立的签名更新 ZIP。签名输入为公证后最终归档。由 Sparkle 工具生成 appcast，指向当前版本的固定 Release asset。正式 Release 在所有资产就绪后发布。保留 GitHub 中旧发行资产。
- 用单测覆盖捕获中、待恢复、后端不匹配、后端失败和正常路径。校验版本、框架运行路径、签名及生成后的 appcast 和 archive，以隔离构建验证，不触碰真实运行数据。Developer ID 公证和 GitHub 资源上线需正式凭据及发布授权。

## 主窗口更新入口

- 工具栏「更新」打开版本说明和下载窗口。进入时读取 GitHub 最新正式 Release，带应用内更新的正式版只显示正式包。可手动分发的构建在尚无正式版时从已发布的预览中选发布时间最近的 Apple Silicon 包。
- 标题、日期和说明来自同一个 Release。下载按钮直接打开对应桌面安装 ZIP，若提供同名 SHA-256 则同时展示校验文件链接。正式版额外提供应用内安装按钮，调用原 Sparkle 门控。
- 区分加载中、当前无匹配安装包和请求失败。公开 API 限额时改读 GitHub 发布订阅并核实对应下载文件。其他失败时允许重试，始终可打开 GitHub 发布页。页面只访问公开发行数据并打开相符的官方资产。
- 用 API 夹具覆盖正式版优先、预览按发布时间、无正式版时的回退以及拒绝错误包和外部 URL。检查真实 Release 返回的说明及链接，执行 Swift 全量和隔离 App 构建。

## GitHub 自动发版

- main 推送中新建一份 `release/desktop-previews/YYYYMMDD-名称.md` 才会发布。该正文作为 Release 更新说明。普通提交、修改已有说明和在验证分支运行构建无需发布。版本名含说明日期和推送提交 SHA。
- macOS arm64 runner 使用现有预览打包脚本。云端复用已发布且对应同一 Android 助手源码树的签名 APK，校验下载来源和 SHA-256。助手源码变更后先更新由同一签名生成的发行基准。保留本地手工打包路径。
- 构建和资源校验以只读仓库权限运行。发布任务写入精确的 tag，创建或恢复同提交的匹配草稿，检查两项资产名、大小和 SHA-256 后公开发布。重复执行跳过已有匹配发布。发版需要新增说明，配置上线不创建 Release。
- 在隔离 Git 历史和受控 GitHub 接口测试发版意图和失败路径，验证实际 GitHub runner 打包与签名、部署后无意外 Release。

## 语义版本与 1.0.0 实发

- 预览版用三段语义版本作为 App 显示版本和 Release 标题中的版本，首次为 1.0.0。说明文件用 `release/desktop-previews/1.0.0-version-check.md` 格式。CI 拒绝其他同级或更低的已发预览版本。保留原有日期及提交 SHA 的标签和文件命名，兼容已分发客户端。
- 从包内读已安装版本。正式版从标签、预览版从约定的 Release 标题读可用版本。版本相同或更高提示「已是最新版」，只有较新发行显示下载。旧无语义版本的发行可用准确构建标识判定同版，无法确定时提供发布页。保留网络失败和无安装包状态。
- 本轮只推送并自动发布新版本，验证公开下载、构建来源、已安装旧版发现和下载版的最新状态。用户的正式安装和抓包运行目录保持原状。
