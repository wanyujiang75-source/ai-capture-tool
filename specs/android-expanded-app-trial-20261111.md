## 目标与不变边界

- 用户要求多测不同应用，再决定是否加入桌面端；未来入口必须位于 Android 下，区分模拟器和真机。
- 延续已授权的临时目标应用转发试验：不 Root、不改源码/APK、不注入、不降级、不关闭安全更新、不读取应用或 VPN 私有数据；原 VPN 节点/订阅/配置、Mac 系统代理不改，每轮结束恢复。
- 不新增测试 CA。仅正常启动及只读导航，不登录、购买、创作、兑换、交易、发帖、改账户或重放业务请求。应用启动自动写请求如实记录，不承诺所有后台请求均为只读。
- 不以银行、支付、聊天、账号管理等无关个人应用扩充样本。新应用未安装或身份无法确认时记录未覆盖，不擅自下载、覆盖或清理安装态。
- 不操作模拟器来冒充真机。不在设备掉线时自动改用另一设备；不同设备重新建立基线、独立关联证据。
- 私有临时目录 0700；每轮最长 900 秒、最多 100 个归档事务/30 MiB、单正文 8 MiB。仅保留脱敏证据，结束清理原文/密钥/自有隧道/下载配置/新增 USB 映射与进程。

验收顺序：

1. 确认唯一目标手机；记录型号、系统/补丁、用户构建标志、目标包版本/来源/全部 APK 摘要，原 VPN 所有者、可见模式/节点/配置、系统代理及 USB 映射。
2. 每应用单独接管流量；先观察目标应用的有界 SNI 元数据确认业务域名，不解密无关应用。各应用独立结果，失败不扩大权限。
3. 至少一个真实业务事务有 Request/Response 头、结束时间、原始正文长度/哈希及可读内层结构。HTTP 200 无正文、仅外层 JSON 密文、静态资源、浏览器对照不能替代业务成功。登录阻塞与 TLS 失败分开。
4. 对重复请求、页面导航、压缩/空正文及上限分别记录实际覆盖；未覆盖不宣称产品级验收通过。无新证据不重复换证书或关校验。
5. 每轮恢复原 VPN；最终原 APK/系统代理/USB 映射一致，原模式/节点/配置可见值一致，自有资源清理；差异检查通过。无法读取私有配置时不声称其文件哈希已核验。
6. 输出逐应用支持矩阵和接入建议，技术实测、实验入口、稳定发行三个层级分别给结论。

## Android 下的入口约束

保留现有“抓包 / 安装应用 / 接口 / 日志”四导航及 Android / iPhone 平台选择。在 Android 内增加二级设备类型：“模拟器 / 真机”。这是后续方案，不是本轮已实现界面。

| 项目 | 模拟器 | 真机 |
| --- | --- | --- |
| 主操作 | 启动/显示模拟器，沿用现有抓包流程 | 检测手机、验证抓包、开始/停止抓包 |
| 未连接 | 提供启动模拟器 | 提示连接 USB 并授权调试，不启动模拟器、不操作其他真机 |
| 环境准备 | 现有模拟器/抓包组件流程 | 只读准入，展示可用路线和必要手机确认；不 Root、不自动安装证书 |
| 结果标识 | Android · 模拟器 · 设备/应用 | Android · 真机 · 设备/应用；实验路线额外标识 |
| 失败 | 保留既有错误及恢复 | 明确区分未验证、仅连接信息、证书拒绝、正文可读、待恢复 |

- 当前 CaptureHomeView 在 IOSCaptureView.swift 中将 Android 直接交给 CaptureView；CaptureView 中启动按钮、引导、弱网条件都依赖 emulator 状态。不能只替换文案就把物理设备交给同一启动流程。
- 设备类型来自后端可信探测，序列号前缀仅辅助识别；不能因“adb device 在线”就当作支持抓包。
- 真机与模拟器分别保存选中设备及状态，切换页面不隐式启动/停止采集或替换 VPN；已有任务始终显示明确归属，不把两个类型的历史接口混为当前结果。
- 复用 NR-0 准入契约时必须明确新路线身份，不能把受损 CA 实验假称为普通 trusted_proxy；历史正文不作为新设备的自动授权。
- 开始前确认设备、目标应用、网络转发和恢复路径。停止后的网络恢复属于成功条件；恢复未确认时显示“待恢复”，不提示已完成。
- 真机日志能力和 HTTPS 正文能力分别判定；没有正文资格仍可使用合规日志功能。
- 断点和弱网默认不因正文成功而启用，需各自验收。模拟器和 iPhone 既有功能不受实验路线影响。

## 是否接入的门槛

1. 至少补齐一个不同网络栈样本，失败也需明确失败层，不能只有同源 Flutter 成功结果。
2. 原包、已修复版本和新设备的能力判定准确；不要求用户停留在漏洞版本。
3. 拔线、代理退出、Mac 休眠、重复停止和重启恢复均有故障注入证据；不能依赖开发者手动清理。
4. 正文及内存限额、隐私脱敏、端点身份、资源所有权和更新后证据失效已验证。
5. 普通稳定路线和安全诊断实验路线分开；即使满足实验门槛，也不默认对所有用户开放。
6. 当前仅完成部分隔离链路验证，以上门槛未全部达到前不集成或发包。
