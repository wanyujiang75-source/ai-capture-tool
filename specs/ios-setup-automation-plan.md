# iPhone 真机抓包配置流程优化计划书 V1.1

> 实施者：按 `superpowers:executing-plans` 逐项执行。2026-11-02仅交付规划；2026-11-03用户授权先执行A1，保护原VPN配置及当前抓包。任务状态以根目录 `progress.md` 为准，不另建实施任务池。

**Goal:** 将支持场景的电脑准备、配置生成、规则生成、交付和验证自动化，手机只保留安全确认与应用操作，不要求新用户手填地址、端口、密码和域名规则。

**Architecture:** 复用现有SwiftUI桌面、FastAPI控制平面、独立mitmproxy及统一接口结果。将证书身份、网络接入方式、配置交付和记录生命周期解耦；Shadowrocket适配须先通过无损导入试验，再纳入正式向导。

**Tech Stack:** SwiftUI/AppKit、macOS Keychain、Python/FastAPI、mitmproxy、Apple配置描述文件；单台iPhone，普通Wi-Fi或经验证版本的Shadowrocket。

**范围:** 2026-11-02规划稿。仅本地开发/验收计划，不包含远端发布、iOS安装/日志/弱网、越狱、证书绑定绕过、MDM部署、其他VPN适配或整个网络的自动解密。

## 1. 评审结论与证据

结论：方向可行，但原方案不能直接按“扫码后全部自动”交付。先完成安全导入和恢复能力验证，再收敛交互；否则只是将人工问题隐藏到“准备中”。

| 级别 | 原流程缺口 | 影响 | 调整 |
| --- | --- | --- | --- |
| P1 | 假设安装Wi-Fi描述文件即可改变实际流量路径 | 已安装但代理仍关闭；开启VPN时可能根本不经过Wi-Fi代理 | 明确普通Wi-Fi/保留小火箭两种模式，以真实手机请求判定生效 |
| P1 | 小火箭节点和规则需要逐字段填写，自动增量导入未验证 | 已出现把密码误填到域名、检查页通过但业务不进代理 | 导入适配作为首项技术门槛；自动生成，用户只确认导入；不覆盖原配置 |
| P1 | 把电脑退出或删除证书等同于手机恢复网络 | 残留节点/规则指向关闭的Mac，手机应用可能断网 | 分离停止记录、断开连接、移除授权；提供按接入方式区分的恢复动作 |
| P1 | 原二维码只指向依赖代理的检查域名 | 代理未生效时只得到“网址无效”，无法定位哪一步失败 | 新引导入口不依赖抓包路由；局域网、代理认证、HTTPS、目标流量分层验证 |
| P1 | “安全扫码”未定义信任建立和传输保护 | 短链接不是加密，公开下载可能泄露临时代理凭据 | 公共证书与敏感配置分开；敏感交付必须受保护且有有效期 |
| P2 | CA、端口、密码与短命worker耦合 | 重启后反复重装证书、更新节点，历史链接容易误用 | 有限期配对身份独立保存，端点按版本管理；有效期内尽量复用 |
| P2 | 未收到请求便提示安装或信任问题 | 无法区分局域网隔离、VPN路由、凭据、证书或应用没有请求 | 状态必须有证据；没有足够证据时显示“尚未收到验证请求”，不猜根因 |
| P2 | 未检查Mac到业务服务的出站链路 | 手机VPN能访问不代表接管后的Mac能访问 | 加入Mac出站检查，不读取或复制手机VPN订阅 |

本地依据：`capture_console/ios_setup.py`将Wi-Fi、CA、检查入口放在一个描述文件并在24小时或地址变化后清理；`ios_setup_api.py`的结束仅确认删除手机配置；`IOSSetupView.swift`仅有共享和检查二维码；`IOSSetupCopy.swift`仍泛称“无需手填代理地址或认证信息”。这是代码核查，不是本轮新增产品测试。

实际证据：现有PokeHub手工辅助链路已收到真实Request/Response，规划时只读复核为26条记录。原配置送达、HTTPS通过和应用请求成功曾分别发生，不能合成一个“连接完成”。详细历史见`ios-desktop-integration.md`，保留未完成的整体验收项。

## 2. 产品边界与验收目标

- 保留四导航；抓包页的iPhone入口增加同一个连接向导，不另建设置迷宫。
- 必要前置条件：iPhone和Mac网络互通、工具运行、所选项目域名已知。USB是可选诊断增强，不要求普通用户安装Xcode或启用开发者模式。
- 手机VPN状态不能假定可被Mac完整读取；首次只询问“是否需要保留小火箭联网”，记住选择，允许更改。
- 已配对且配置有效时，不重新手填参数、不重复安装证书；有新配置时只要求导入确认。到期、撤销或换Mac必须明确重新授权，不承诺永久免配置。
- 安装/信任只代表连接准备。必须由用户点击“开始抓包”表达记录意图；可在其点击后自动推进准备，页面保留“取消准备”。打开工具、收到回调或后台重连不得自动恢复录制。
- iPhone按所选项目域名筛选，不宣称能自动识别任意前台应用或只捕获某个进程。HTTPS检查成功不等于所有项目均可抓取。
- V1不支持证书绑定应用、非代理流量、任意QUIC/UDP解密或WebSocket消息解析；无法捕获应准确提示，不关闭TLS校验。

## 3. 优化后的使用流程

### 3.1 首次连接

1. 桌面选择iPhone、目标项目，以及“普通Wi-Fi”或“保留小火箭”。有现成项目时无需输入域名；新增项目由维护者录入并校验，不能从未知加密流量凭空生成完整域名表。
2. 桌面自动检查本机服务、局域网地址、端口、目标域名的Mac出站链路，生成本次身份和版本化配置。发现端口被其他程序占用时选择允许的新端点或报错，绝不结束他人进程。
3. 手机接收证书配置并确认安装、信任。桌面显示唯一名称及短指纹，避免安装旧文件或信任错误证书；首次配对是否“信任此电脑”只在USB增强模式需要。
4. 桌面生成模式专用的网络配置；手机确认导入。小火箭保留原节点及VPN，只增加所选项目和检查域名的测试路由；普通Wi-Fi配置必须实测生效，失败不能默默改为让用户手填。
5. 手机打开一个验证入口，页面自动执行允许的连接检查并回传阶段结果。桌面不要求用户反复回答“完成了吗”；无法自动打开页面时保留一次点击/扫码动作。
6. 若此前点击了开始，验证通过后自动进入该次抓包；否则显示“iPhone已连接，尚未开始抓包”。用户操作应用，真实业务响应进入统一接口页后才显示“已收到目标接口”。

手机保留的是三类确认，不承诺总共只点击三次：安装配置、证书信任、第三方客户端导入/启用。需要账号登录或项目操作时仍由用户本人完成。普通手动安装证书不会自动获得SSL信任，参考[Apple官方说明](https://support.apple.com/en-gb/102390)。

证书配置和网络配置分离后，普通Wi-Fi首次使用可能有两次安装确认；界面应逐项展示，不用“三步完成”掩盖实际点击数。小火箭模式的证书配置不包含Wi-Fi代理载荷。

### 3.2 再次使用和切换项目

- 同次连接停止再开始：复用连接，创建新记录；不重新安装或导入。
- 有效期内重开桌面：恢复本机服务与配对身份，但不恢复录制；有可达证据后用户点击开始。无最新手机验证时显示“等待重新验证”，不能沿用旧ready标记。
- 项目域名已在当前已导入版本内：切换记录范围即可；新增域名时生成增量更新，只要求手机确认一次导入，不换CA。
- 地址或端点变化：旧导入版本失效，保留当前CA直到到期，交付新网络配置并重新验证。不把同SSID当作连接地址未变的证据。
- 配置到期/被移除/更换主机：明确告知需要重新安装或导入哪些部分；不反复让用户重做所有步骤。

### 3.3 停止、断开与恢复

| 操作 | 自动行为 | 必要手机行为 |
| --- | --- | --- |
| 停止抓包 | 停止记录，保留连接，目标流量透传，历史保留 | 无 |
| 断开iPhone | 先停止记录，进入恢复向导；确认路由恢复后停止代理 | 小火箭撤销本工具增量或切回原配置；普通Wi-Fi恢复原代理配置 |
| 移除授权 | 撤销配对、销毁密钥/下载凭据、清理本机临时文件 | 删除本工具描述文件；如遗留手动代理也需恢复 |
| 退出桌面 | 提示还有手机路由依赖；正常退出清理自有进程并保留恢复说明 | 先恢复手机路由；强制退出后仍可能需要手动恢复 |

不能静默改小火箭的全局节点、FINAL或DNS，不能用“失败后DIRECT”替代原VPN路由。自动回退必须在兼容性试验中证明确实回到原路径；否则明确保留手机恢复动作。桌面无权删除第三方配置时，不显示“已自动恢复”。

### 3.4 切换小火箭节点（2026-11-03新增验收）

- 只切换日常VPN出口节点：所选项目仍应由精确规则指向独立抓包节点，不依赖首页选中的普通节点。CA和Mac端点未变时，不应重装证书或重填抓包配置；切换可能短暂重连，由新的连通性检查判断恢复。
- 切换整份配置、改变全局路由模式或订阅更新：可能移除/覆盖测试规则，不能与普通节点切换等同。需要检查本工具规则版本，缺失时提供重新导入，而不是要求重装CA。
- VPN关闭或Mac地址/端口/证书到期：按实际变化重新验证或更新连接，不能用“换节点无需处理”掩盖配置失效。
- 抓包流量经过Mac的出站链路，未必经过手机新选的VPN出口；此方案不承诺保留节点地区/出口IP语义。切换节点用于验证地区行为时应先停用测试路由，或另做经明确授权的上游设计，本轮不自动复制订阅或改变Mac代理。
- A1需分别验证普通节点切换、规则保留及撤销后的原路径。未完成实机前，以上作为设计契约而非已通过结论。

## 4. 技术设计与安全约束

### 4.1 网络模式适配器

- `wifi_proxy`：生成适用于选定网络的代理配置。Wi-Fi名称不可读时手填一次；企业账号Wi-Fi不自动覆盖。Apple的schema支持Manual/Auto代理，不代表所有已连接网络都会即时应用，仍须实测。[Apple配置定义](https://github.com/apple/device-management/blob/release/mdm/profiles/com.apple.wifi.managed.yaml)
- `shadowrocket`：首选经测试的增量模块/导入工件，包含专用节点、明确项目域名和检查域名。所有工件带本工具标识、版本及归属，只更新自己创建的内容。
- 不假设已有可用URL scheme或自动合并API。官方只确认规则文件导入能力，没有据此保证节点与规则原子追加。[Shadowrocket官方功能说明](https://apps.apple.com/us/app/shadowrocket/id932747118)
- 如果增量导入不可行，仅在用户主动提供本地导出配置时生成独立临时副本；原文件不变，界面预览仅本工具节点/规则的差异，未知语法或无法完整保留时拒绝。该备选需要额外操作，必须标为受限模式，不能算“仅必要确认”目标已达成；不自动拉取订阅或扫描凭据。
- 导入工件包含检查规则和完整项目规则快照，禁止通配全部流量；重复导入幂等，项目域名校验复用`ios_projects.py`。
- Mac出站失败应提示检查Mac网络或用户已配置的代理，不假定手机VPN会替Mac转发。自动探测仅针对已选域名的DNS/TLS或明确安全检查地址，不调用有业务副作用的接口、不记录账号信息。

### 4.2 安全交付与二维码

1. 首次建立证书信任前，敏感配置只通过系统保护的本地文件共享交付；不把代理密码直接放进二维码、剪贴板默认操作、公开URL、云盘或日志。AirDrop只由用户选定自己的手机，系统“等待中”不算送达。
2. QR作为辅助入口而非唯一入口：初始可展示不含凭据的引导信息，不能宣称HTTP下载页安全。首次CA通过已确认共享建立信任后，才启用本机HTTPS配置下载；证书须匹配实际访问地址，不能要求浏览器忽略警告。
3. HTTPS交付验证通过后可作为后续配置更新主路径；小火箭实际能否使用系统信任访问该下载服务属于A1/A2实机验证内容。未通过则保留文件导入，不降低TLS验证。
4. 本机控制API仍只绑定回环。交付服务独立监听选定LAN接口，只允许固定工件，不提供目录、运行日志、认证原文件或私钥；拒绝非白名单路径、非预期方法及跨站请求，不接受任意文件读取。
5. 下载票据至少128位随机、10分钟有效、绑定配对和配置版本、最多3次成功下载；版本替换/断开立即撤销。无票据/过期/错误版本请求拒绝；请求日志及错误报告不得泄露URL票据。
6. 工件写入本机私有目录、权限600；含凭据工件默认10分钟后或确认导入后删除，可由用户主动重新生成。私钥不进入手机描述文件、导入工件、诊断包和发行包。
7. HTTPS交付不等于HTTP代理认证已加密。普通Wi-Fi代理只允许受信任局域网及短期独立凭据；小火箭若支持并通过测试，优先使用TLS保护的代理接入。不对不可信公共Wi-Fi宣称安全适用，不复用公司账号密码。

### 4.3 配对身份与端点复用

2026-11-03用户新增要求避免短期失效，独立IOS-C1先实现一年期CA/身份复用及Keychain保管，详见 `ios-certificate-reuse.md`。下面24小时策略为原评审历史，已被该新增规格覆盖；A2的交付票据与A1的自动导入仍保持待验收，不因C1自动完成。

- V1保持24小时有限期授权，不延长为永久信任；CA身份和路由配置分开，应用重启不等于强制更换CA。证书有效期、描述文件自动移除期限与服务到期时间对齐，不仅在界面设置一个到期标记。
- CA私钥和代理密钥由本机Keychain按配对标识保存；worker需要的临时材料仅在运行时私有目录出现，退出回收。重启恢复先核验到期时间、归属及Keychain可用性；不得回退到长期明文配置保存。
- Keychain只用于本工具自己的条目，不读取Wi-Fi密码、VPN节点或第三方条目。应用签名/升级导致条目访问受限时进入恢复流程，不降级安全策略。
- 有效配对优先复用原端点和凭据，减少重新导入；不复用已撤销材料。地址变化或端口冲突产生新`config_revision`，旧回调、下载票据和路由确认不能推进新状态。
- 仅支持一个活动手机配对。认证请求来自私网地址不是硬件身份认证；有USB证据才显示具体设备名，否则显示“当前配对iPhone”。来源变化要求重新验证，不自动关联另一台手机。
- 升级时现有一体式临时配置继续按旧逻辑工作，不在活动抓包中迁移密钥或替换配置。用户发起结束并恢复旧手机路由后，再创建新版配对；旧客户端与旧描述文件的剩余恢复步骤必须可见。

### 4.4 分层状态与接口

准备状态按`idle → checking_host → awaiting_phone → awaiting_route → verifying → ready`推进，允许`recoverable_error / expired / restoring`。记录状态沿用现有独立`idle / recording / stopped / failed / limit_reached`，取消准备或重启清除待开始意图。

检查项固定为本机服务、手机到Mac、代理认证、HTTPS、所选项目范围、Mac出站。每项结果包含`state`（unknown/checking/passed/failed）、`evidence_source`、`observed_at`和`recovery_action`。应用响应单独显示，不作为初次准备必须等到的前置条件，避免“未开始抓包就要求已收到业务响应”的循环。

状态证据要求：
- 文件生成/分享/下载都不等于安装；可用USB只读查询仅证明描述文件存在，不能证明TLS信任或路由已生效。
- 本机自检不得设置手机ready；只有当前代际、认证成功、受控HTTPS验证请求来自目标手机连接才满足准备通过。
- 检查域名通过但项目未收到请求：显示“连接已验证，等待目标接口”，提供规则复查，不武断宣称证书有问题。
- 未出现TLS证据时不直接断言未信任；显示“尚未完成HTTPS验证”，技术详情解释观测结果。
- 业务证明须有真实目标域名请求；页面展示成功需要真实状态码和正文可读性，不要求每条都200，也不把合法204当失败。
- 断开恢复分成`user_confirmed`和`verified`；无法独立读取手机设置时只能标记前者。

拟增量接口（保留现有字段及旧客户端行为）：
- `POST /api/ios-setup/prepare` 增加可选`network_mode`、`project_id`、`resume_pairing_id`；旧请求仍走原模式，新模式不以SSID作为唯一身份。
- `GET /api/ios-setup` 增加`pairing_id`、`network_mode`、`config_revision`、`expires_at`、`checks`、`next_action`；绝不返回明文凭据或私钥。
- `POST /api/ios-setup/delivery` 接收`artifact_kind`与`config_revision`，返回短期交付描述；普通状态轮询不刷新或暴露下载票据。
- `POST /api/ios-setup/verify` 发起有界、只读验证并返回检查项，不把用户点击“已完成”当作代理通过。
- `POST /api/ios-setup/restore` 接收`config_revision`、`route_restored`、`profile_removed`；区分保留有效授权的断开与彻底移除授权。旧`/stop`兼容旧确认字段，只按旧恢复语义处理。

## 7. 验收矩阵和完成定义

| 场景 | 通过标准 |
| --- | --- |
| 新手机 + 普通Wi-Fi | 从桌面准备到真实目标请求；系统确认之外不手填技术参数；若系统不应用配置，明确阻塞，不报成功 |
| 新手机 + 小火箭 | VPN保持开启；导入节点与规则免手填；无关流量沿原路，原配置可恢复 |
| 共享失败/隔空投送不可见 | 不重复生成CA；保留有效配置；提供经过验证的安全替代交付入口，不选择错误设备 |
| 局域网隔离/代理未生效 | 定位到有证据的连接阶段；不让用户盲目重装证书或改DNS |
| 认证错误/证书未信任 | 明确区分已收到连接与HTTPS通过；正常安全确认后自动继续 |
| 检查成功但项目规则遗漏 | 不显示已捕获业务；提示更新项目配置并验证真实目标请求 |
| 停止再开始 | 同一配置连续3轮，无重新安装；停止后无新增记录、手机联网正常；开始后为新记录 |
| 有效期内重启 | 连续3轮不更换CA、不自动录制；当前验证通过后才可开始；端点改变时仅要求更新路由 |
| 地址改变/占用/到期/撤销 | 旧配置不被当作有效；旧票据失效；不结束其他程序、不关闭VPN、不保留无限期信任 |
| 旧版升级 | 当前旧连接和记录不被升级静默替换；用户恢复旧配置后才切换新配对；旧客户端返回语义保持兼容 |
| 正常断开/强制退出 | 正常恢复路径可操作；强退后的手机恢复说明离线可读；不声称强退能远程删除手机设置 |
| 真机业务 | PokeHub至少3条真实请求及可读响应；另一个受控域名验证范围隔离；探测请求和业务请求分开统计 |
| 跨平台共存 | iPhone录制/停止不改变Android任务、端口、日志和网络设置；两个来源结果不串入 |
| 安全交付 | 未授权、过期、错误版本、下载超限、路径穿越被拒；工件及包不含私钥、生产凭据或抓包数据 |
| 新用户安装 | 第二台Mac或明确全新用户环境实际操作；结果区分实体新主机与本机隔离；说明能引导安全恢复 |

体验目标：支持场景下技术字段手工输入为0；手机只保留必要确认、打开检查入口和应用操作。准备与验证必须显示当前阶段，单项5秒无结果说明等待原因，30秒仍无结果提供重试/恢复，不无限转圈；需要用户确认的等待不按30秒超时自动重置。墙钟耗时包含人工等待，不承诺固定“三分钟完成”。

完成必须同时满足：A1兼容范围明确、A2-A5回归通过、A6真实矩阵有证据、安全和恢复通过、安装指南更新。任何受限路径或未完成实机项都单独列出，不把“代码已写完”写成“所有iOS应用可用”。
