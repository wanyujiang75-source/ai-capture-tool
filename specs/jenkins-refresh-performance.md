# Jenkins 安装包刷新慢

记录日期：2026-10-22。2026-10-26 已在本机修复并验收；下列历史测量保留。尚未推送或发布安装包。

## 现象与实测

- 桌面构建 weak-network-presets-20261020，Jenkins 查询代码与当前工作树校验值一致。
- 本机安装包列表 API 返回 HTTP 200，耗时 9.210 秒，响应 12,830 字节；设备查询另需约 0.522 秒。
- 按现有逻辑逐请求计时：任务索引 0.073 秒、38 个任务；过滤后共 36 次串行请求，总计 10.064 秒，返回 31 个安装包，无查询错误。
- ai-music-apitest 单任务耗时 6.796 秒。独立复核同一查询耗时 6.723 秒，返回 5,698,466 字节，最近 10 个构建中含 43,020 条报告产物，无 apk/apks/zip 安装包。
- 这些是当次样本，不是持续性能保证；不将本次正常 HTTP 200 推断为此前连接错误的确定原因。

## 根因

- `capture_console/jenkins_source.py` 默认排除 api-test，但未覆盖 apitest，误读接口测试报告任务的完整产物列表。
- 每次刷新串行获取每个任务最近 10 次构建及产物，未利用缓存或构建变化信息；单个慢任务阻塞整份列表。
- `AppState.refreshWorkspaceData` 先等待设备刷新，再查 Jenkins；安装包刷新没有合并重复请求。
- `DeviceAppView.jenkinsContent` 在 loading 时隐藏已有列表，仅显示等待动画，放大用户感知延迟。

## 后续修复建议与验收

1. 精确排除非安装包任务，覆盖 api-test/apitest 命名；测试不得误排正常应用任务。
2. 优先查询轻量构建信息，复用未变化构建的产物结果；手动刷新仍检查新构建，失败不伪装成最新数据。
3. 用有界小规模并发查询并合并重复刷新，限制服务器负载；慢任务、权限失败要有明确部分失败状态。
4. 刷新保留已有列表并显示更新状态；验证成功替换、失败保留、重复点击和切页行为。
5. 保持“最近构建中成功且有可安装产物”的选择语义，覆盖最新成功构建无 APK、旧构建有 APK 等回归。
6. 同网络条件记录优化前后总耗时、请求数、响应字节和列表一致性；不得靠删去有效安装包提高速度。

最初一轮只记录；本次修复仍不修改服务器配置、不触发构建、不下载或安装 APK、不发布远端。

## 实施设计（2026-10-26）

- 每次显式刷新读取一次 `jobs[name,color,builds[number,result,timestamp]{0,N}]`，不在索引中读取产物。真实服务已验证支持此查询。
- 任务产物按最多 4 个工作线程读取，按构建顺序查找第一个成功且含安装包的构建。默认 api-test 排除规则同时覆盖同一命名的 apitest/api_test，不扩展成排除任意含 test 的应用。
- 成功产物查询缓存以任务、构建号、时间戳为键，最多 256 条、有效期 300 秒；包括空产物结果，失败不缓存。新构建立即查询，过期重新验证；安装接口仍重新校验产物。
- 同时到来的刷新共享同一个 Future；每个调用获取自己的结果副本，错误随同一结果返回，不从跨请求共享 last_errors 拼装响应。
- API 保留 packages/source 兼容性，新增 source.failed_jobs，原始诊断不直接展示。部分失败只保留这些失败任务的旧包，明确显示“部分任务刷新失败”；完整失败保留旧列表并明确提示未更新。
- 桌面按钮只刷新安装包，不先等设备查询；请求进行中防重复，已有列表不被加载或失败占位替换。设备仍由已有轮询独立更新。
- 回归覆盖成功构建无包回退、失败/运行中构建、任务过滤、缓存命中/过期/上限/新构建、并发上限/合并/错误恢复，以及 UI 成功/部分失败/失败保留/重复刷新/旧服务兼容。

API 使用 Jenkins 官方 [Remote Access API](https://www.jenkins.io/doc/book/using/remote-access-api/) 的任务/构建只读接口；不增加服务器插件或鉴权方式。

## 验收结果（2026-10-26）

同一 Jenkins、同一网络，旧版代码与新版均使用相同只读请求计时器，返回 31 个安装包且无任务错误：

| 样本 | 总耗时 | Jenkins 请求数 | 接收字节 |
| --- | --- | --- | --- |
| 旧版 | 10.962 秒 | 36 | 5,194,498 |
| 新版首次读取 | 1.697 秒 | 39 | 29,560 |
| 新版后续刷新 1 | 0.249 秒 | 1 | 24,058 |
| 新版后续刷新 2 | 0.175 秒 | 1 | 24,058 |

冷读取因无安装包构建的回退，请求数略增，但不再下载多次构建的大量报告清单。缓存仅复用完成构建的产物信息，表中每次后续刷新仍读取新构建索引；不能将样本速度当作网络持续保证。

- 原桌面 API 9.618 秒；最终嵌入式后端 API 0.204 秒，`build_id=jenkins-refresh-20261026`；前后完整 packages 数组经排序 JSON 比较完全一致，不仅比较数量。
- Python：`python -m unittest -q tests.test_jenkins_source tests.test_console_api tests.test_console_core tests.test_package_install tests.test_flutter_proxy_unpin_capture`，210 项通过。8 项 Jenkins 查询测试覆盖缓存、回退、并发、过滤、错误隔离和恢复。
- Swift：`swift test --package-path macos-native --skip appDelegateReopensAnExistingHiddenWindow`，94 项通过；已有 AppKit 窗口测试独立运行，1 项通过。新状态测试确认重复刷新不产生第二请求，刷新与失败保留旧列表，部分错误不会显示原始诊断。
- 使用本项目缓存运行时构建桌面端，经原生 UI 打开“安装应用”并点击“刷新安装包”，列表与搜索区域正常显示。加载保留/失败保留由状态回归覆盖；实际正常刷新很快完成，未将未捕获到的中间帧记作截图证据。
- 启动后的首个列表请求曾出现一次 502，随后自动加载和手动刷新均返回 200；保留该实测，不宣称内网永不失败，未通过隐藏失败换取速度。
- 构建、运行后的 `codesign --verify --deep --strict` 和 `git diff --check` 通过。桌面保留打开，不启动抓包、不下载或安装 APK；未更改模拟器网络或应用数据。根工作区原有未跟踪使用流程文档校验值未变化。
