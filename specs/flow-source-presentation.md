## 范围与决策

FLOW-UX1 只优化接口页，不扩展为全部导航重设计。当前下拉将停止和失败记录与固定 Android 入口混排，泛化 iPhone 名称重复；历史空记录提示操作手机，容易被误解为正在抓包。

采用当前摘要 + 历史面板，而非另一个默认铺开的长下拉：
- 默认只选正在运行的记录；优先沿用当前 Android 任务，否则选正在运行的 iPhone，不自动选旧记录。
- 当前任务摘要显示名称/平台/状态，多个运行任务才显示“切换抓包”；未运行不显示虚假的 Android 来源。
- “历史记录”面板只列非运行记录，以应用、日期时间、状态和记录编号区分；支持搜索与刷新，不删除或合并原始数据。
- 选择历史后保留该记录、请求详情和既有分页隔离；“返回当前抓包”才切回当前。新任务不抢占历史选择。
- 普通说明收敛成“查看请求与响应，支持搜索和筛选。”；无任务、历史无请求、已清空、加载、失败明确区分；停止/失败不标实时，也不提示用户操作设备触发请求。
- 新文案统一 AppCopy；原 API 可选解码 started_at，旧归档缺日期仍可看。保持搜索/仅看接口/断点/完整 URL/大正文保护。

## 自审

自动删除历史会损失证据，按设备合并历史会混淆时间段，均不采用。未知来源状态保留历史访问且不声称实时。显式选中的 iPhone 记录停止后继续可读但标历史；Android 沿用原有停止后重置当前视图的行为，结果仍可从历史面板打开，本轮不修改启停链路。刷新失败不丢弃旧选择。BP-4 等其他任务状态不变。

来源与请求采用独立轮询：来源列表即使无任务也刷新，请求轮询按记录编号绑定生命周期。切换记录立即取消旧请求，不必等待旧记录的慢响应；未加载完成显示同步状态，不提前声称无数据。Android 设备状态滞后时，来源 API 已结束的记录不能继续作为当前任务，也不能挡住唯一运行中的 iPhone。
